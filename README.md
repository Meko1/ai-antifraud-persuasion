# AI 反诈劝阻

> **用户自己正要清仓或大额转出的那一刻，App 里弹一次三分钟对话：
> 让他去劝一个和他处境一模一样的人。**

不是投顾训练器，不是反诈科普，不是聊天游戏。
**是券商在用户按下确认之前的最后一次干预。**

---

## 一、它为什么不是又一个风险提示弹窗

弹窗要求用户**先承认自己可能正在被骗**，才谈得上读下去。这是它最贵的一件事，
也是它从来做不到的一件事——正在转账的那个人，恰恰是最不肯承认的那一个。

角色对调把这笔认知成本整个挪走了：**他不需要承认任何事，他只需要去劝别人。**
屏幕对面那个人和他同龄、进了同一种群、说着同样的"再等一天就来不及了"。

**他劝不动"老陈"的那一刻，会自己想到自己。**

这一条不只是推断。这类骗局会要求受害者签保密协议，**明确禁止向证券公司、
监管部门、公安机关透露任何信息**（证券时报／中证协）。而《反电信网络诈骗法》
给银行与支付机构备的动作是"核实交易情况、重新核验身份"——**两个都是问答，
而对面那个人已经被预先训练成会撒谎**。角色对调不要求披露、不要求承认，
是这套预设防御目前唯一绕得开的形态。出处与它**不能**支持什么，
一并写在 [docs/EVIDENCE.md](docs/EVIDENCE.md)。

## 二、三个问题，一页答完

| | |
|---|---|
| **接哪个信号** | 清仓（持仓一次性归零）／大额转出（占账户资产超阈值）／与历史行为显著背离的赎回（五年只做定投的账户今天全部赎回） |
| **归哪条线** | **用户风险与合规条线**，不是培训条线。推力是投诉与声誉：某券商 2025 年假冒案件线索超 1900 条、同比 +280%、总部来访受害者 150 人次。**不是法条**——《反电信网络诈骗法》的义务人里没有证券公司，见 [docs/EVIDENCE.md](docs/EVIDENCE.md) |
| **怎么衡量** | **24h 内转出放弃率 / 撤单率**，干预组 vs 对照组。护栏指标：完成率、弹出后直接关闭率、30 天二次触发率。**不是"取消率"**——银证转账实时划转，执行后无可撤销，理由见 [docs/EVIDENCE.md](docs/EVIDENCE.md) |

那三条触发信号**不是新写的需求，产品里已经有了**：`Scenario.facts` 里那几行
`warn=True` 就是照它们写的（「今日转出 ¥100,000 / 占 78%」「五年零主动交易，
今天一次清仓」）。在旧定位下它们是布景，转向之后它们是**触发条件**。

> **必须能和对照组比。** 触发异动的人本来就有一部分会自己放弃——没有对照组，
> 干预组的放弃率是一个无法解释的数字：既证明不了有效，也拦不住有人拿它去
> 证明有效。对照组走现行的风险提示弹窗，不是"什么都不给"。
> 口径与"为什么现在不设目标数字"写在 [docs/POSITIONING.md](docs/POSITIONING.md)。

## 三、技术上它凭什么

**判分的算术完全由程序的规则表求值，模型只负责演**（[ADR-0001](docs/adr/0001-scoring-authority-belongs-to-the-program.md)）。
参数由两万局蒙特卡洛标定，纯函数、可离线重跑。

它判的**不是"说得标不标准"，是"用得是不是时候"**——这是同类产品里没有的那一条。
七把钥匙（问用途 / 提问 / 拆矛盾 / 反映式倾听 / 支持自主 / 确认理解 / 有据告知）
每一把在对方四个情绪档位上值不同的分，而**没有一把是"给建议"**：
劝阻方是持牌投顾，荐股是执业禁区，所以只能问，不能荐。

**五个场景**：荐股群（贪）、冒充公检法（怕）、杀猪盘（情）、刷单返利（困）、
虚拟币量化（负）。共用同一张判分表，而四个情绪档位上的最优解
**两两之间至少 2/4 档不同**——这是"能力可迁移，不是背下一个剧本"唯一能被
直接验证的地方，由 `tests/test_balance.py` 两条测试守着。

换模型不影响任何一个分值，只影响演绎质感与分类准确率。这句话现在可以被证伪：

```bash
python -m tools.classify_eval --model <另一个模型> --protocol openai \
  --base-url $INTERNAL_LLM_BASE_URL
```

## 四、主张边界

> 这一段刻意写得比宣传口径保守，因为本项目最值钱的资产是文档诚实，
> 而一处越线的主张会把整套文档一起打折。

- 它是**原型**，不是已验证有效的干预系统。判分规则、人设占比、效力矩阵都经过
  内部标定，但**没有经过业务专家验证，也没有真人对照研究**——内部自洽 ≠ 现实有效。
- **"可复现"指判分算术，不指端到端。** 规则表是纯函数、可离线重跑；但喂给它的
  标签来自会波动的模型分类器，同一份标注集两次连跑实测差 0.6~1.3 个百分点。
  所以门槛一律看两次跑批（§9.3）。
- 复盘给的是**动作与时机的画像**，不是能力认证。
- **上面那两个效果指标一次都还没量过。** 它们需要接进真实异动流水才有数，
  现在写在这里的是口径，不是结果。
- 场景目前是随机分配的。真接进 App 之后，**该由用户自己的异动类型决定给他哪一个**。

## 五、代码里为什么还都写着"投顾"

界面上你是"李经理"，客户档案、执业红线、话术失误这些词遍布代码。
**这不是没改干净，是刻意留的**：

坐在李经理那个位置上的人变了（从受训投顾变成异动用户），
**判分表一格没动**——因为要练的动作是同一套：在不能替人做决定的前提下，
把一个已经做完决定的人拽回来问两个问题。
转的是那一页定位，不是那一套代码。

> 产品身份（核心矛盾 / 成功标准 / 不做什么）写在
> [docs/POSITIONING.md](docs/POSITIONING.md)。**提需求之前先拿那一页量一遍**，它是尺子。
> 这次转向的完整执行清单与逐项结果在 [docs/PIVOT-C-END.md](docs/PIVOT-C-END.md)。

## 本地运行

需要 **Python 3.10+**。

```bash
./stop.sh && ./install.sh && ./start.sh
open http://127.0.0.1:21818/
```

改完 Python 必须 `./stop.sh && ./start.sh`——静态文件是实时读盘的，Python 不是。

## 关键约束

| 项 | 值 | 说明 |
|---|---|---|
| 对外端口 | **21818** | 平台强制固定，改了作品打不开 |
| 生命周期顺序 | `stop → install → start` | 平台固定执行顺序 |
| 脚本位置 | ZIP 根目录 | 不能多套一层项目目录 |
| 目标系统 | CentOS 7.9 | 自带 Python 3.6，**需预装 3.10+** |
| Redis | 5.0.14 | 以实际环境为准 |

### 为什么用 plain uvicorn 而不是 `uvicorn[standard]`

`uvicorn[standard]` 会拉入 uvloop 与 httptools，这两个包在 CentOS 7.9 的老 gcc 上需要
现场编译，是部署失败的高频原因。纯 h11 实现的性能足够本作品使用。

### 为什么 PID 文件放在 `~/.ai-antifraud-persuasion/`

重新部署时平台执行的是**新服务包**里的 `stop.sh`，而解压目录每次都会变。
PID 文件若放在解压目录，新版本的 `stop.sh` 就找不到旧版本的进程。
放在 HOME 下的固定路径才能跨版本稳定定位。

`stop.sh` 还有一层兜底：PID 文件丢失时从端口 21818 反查监听进程，
并用进程特征 `app.main:app` 二次确认，确保不会误杀同机器上的其他作品。

## 配置

复制 `.env.example` 为 `.env` 后填写。**`.env` 绝不可提交入库**。

拿到服务器后第一件事是访问 `/healthz?probe=1`：它会探测当前 provider 的网关连通性。
若内网网关不可达，把 `LLM_PROVIDER` 改成 `public` 即可切到公网模型，无需改代码。

两个默认关着的开关，打开之前先读对应的那一节：

| 变量 | 默认 | 打开之后 |
|---|---|---|
| `TRANSCRIPT_RETENTION` | `false` | 脱敏后留存对局语料（[ADR-0006](docs/adr/0006-transcript-retention-for-the-pivot.md)）。**聊天页那句告知会自动跟着变**，页面上写的与服务端做的不会走散 |
| `OFFLINE_DEMO` | `false` | 离线演示模式，一个网络请求都不发。`/healthz` 会报 `offline_demo: true`——**看不出来是演示的演示，不是演示** |
