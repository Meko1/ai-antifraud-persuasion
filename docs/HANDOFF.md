- **`temperature` 在这个模型上已废弃**，传任何值都 400。分类器因此失去确定性旋钮，

## 分类器标注集怎么用（§9.3）

改了 `CLASSIFY_SYSTEM_PROMPT` 就重跑一次，几毛钱的事：

```
.venv/bin/python -m tools.classify_eval --limit 10   # 先确认链路
.venv/bin/python -m tools.classify_eval              # 全量 + 门槛校验
```

**四道门槛**，任一不过退出码非零：`hit_keys` ≥ 85%、`grounded` 全样本 ≥ 80%、
`grounded` 有钥匙子集 ≥ 80%、**`grounded` 复读攻略子集 ≥ 93%**。

最后那道是这次做出来的关键发现，别当成可有可无的附加项：
总体 85.5% 达标的那一次，复读攻略子集只有 64%，把泄漏率代回蒙特卡洛，
**parrot 胜率从 10.9% 飙到 69.6%**——§9.4 的 20% 上限被击穿，而总体指标毫无察觉。
93% 这个数字是从平衡模型反推的，推导过程写在 §9.3 和 `PARROT_GROUNDED_FLOOR` 的注释里。

标注集自身的质量由 `tests/test_classify_eval.py` 守着（不调模型，进 CI）：
规模、闭集、难例覆盖、扎根比例、复读攻略必须标未扎根。**加标注前先看文件顶部的五条约定**，
尤其是"一条样本最多标一把钥匙"——蒙特卡洛的人设每轮最多出一把钥匙，
允许双钥匙会让单轮上限从 25 变 45，§9.4 的标定直接失效。

## 前端结构（§8）

原生 HTML/JS，零构建，三个文件。`package.sh` 已整目录打包。

- `static/index.html` — 结构（首页会话列表 + 聊天页）
- `static/style.css` — 设计令牌与全部样式
- `static/app.js` — SSE 解析、K 线绘制、复盘、分享卡

**界面语法整体照搬微信**，这是全部设计决策的根。理由不是"微信好看"——微信恰恰
极度克制——而是这类荐股骗局本来就发生在聊天软件里。玩家在这套熟悉的语法里劝阻，
等于站在事发现场，一眼就知道每个东西是干什么的，不用学，也就不需要教程。

**一切都借微信本来就有的槽位，不新造控件**：

| 游戏里的东西 | 借的是微信的 |
|---|---|
| 判分卡（±分、命中标签） | 系统提示（显示"你撤回了一条消息"的那条） |
| 对局状态（信任度、剩余轮次） | 群公告条 |
| 结局 · 转走 | 转账凭证截图，橙卡，`已被对方接收` |
| 结局 · 劝住 | 同一张卡的作废态，灰卡，金额划掉 |
| 结局 · 被拉黑 | `对方开启了朋友验证，你还不是他（她）朋友。` |

**首页那六条会话就是全部铺垫**，一句旁白都不用写：老陈（未读红点，唯一能点的）、
启航财经群（他被拉进去的那个群）、招商银行（他今早划走了十万）、
老伴（这笔钱家里等着用）、小雨（**女儿劝过，而且劝失败了**）、国家反诈中心
（官方提醒他也划掉了）。第五条最要紧：玩家读完就知道"这是诈骗"四个字没用，
而这正是判分引擎里 `bare_assertion` 要扣分的原因。

开局请求在玩家读这一屏时就发出去了，点开会话时开场白通常已经到手——
「首屏 ≤3 秒」是被会话列表那一屏顺手买的单。

**只有一个颜色不属于微信**：`--gold`，专供游戏层（劝住线、复盘里最有力的那一轮）。
留一个外来色，是为了让"这是一局游戏"和"这是一次真实对话"能被一眼分开。

**视觉取自老陈自己的世界**：信任度画成红涨绿跌的 K 线（荐股群那套配色）。
一根蜡烛一轮，实体是信任度起落，细横线是判分给出的分数——两者的落差就是
每轮的信任流失与蓄势池的存取。

**K 线只在复盘里，分享卡上没有它**（这一句以前写反了）。分享卡是一张**聊天截图**：
主体是老陈说过的那一句话，成绩退到卡底一行。理由是人们不发自己的成绩，
发的是 AI 说的那句话——一个同行看到「免责协议那是行规，你外行不懂」会心头一紧，
因为他上周刚听客户说过差不多的话。K 线留给复盘，那是给认真打的人和评审看的。

**SSE 走 POST**，所以不能用 `EventSource`（它只发 GET），`readEvents()` 自己解协议。
`score` 在台词播完后才到，前端据此播信任度动画——这个顺序是刻意的，别改。

## 踩过的坑（别再踩一遍）

1. **`delta` 语义**：只记判分结果，**不含信任流失**。依据是 §7.2 样例里 `d:20` 恰等于基值。
2. **取整规则**：权重相乘必出小数，实现是**求和后一次性四舍五入、对负数对称**（`_round_half_up`）。
   改这里会动摇蒙特卡洛结果，§3.5 脚注那条测试会红。
3. **兜底台词绕过安全层直发**，所以必须自身安全。`app/fallback.py` 顶部有说明，
   加词后跑一遍安全层自审。
4. **开场白必须进 session，而且要一路带下去**。它是第 1 轮唯一可供"扎根"的内容。
   曾经两次断在这儿：一次是没进 session，一次是 `play_turn` 建下一个 session 时把
   `opening` 丢了，令牌从第 1 轮之后就没有开场白了。回归测试：
   `test_开场白与历史都要送到网关手里`、`test_开场白要一路跟着令牌走`。
5. **`STATE_SIGNING_SECRET` 缺失时服务拒绝启动**。CI 里已经配了一次性值。
6. **`.env` 里有真实 API key**，已被 gitignore 和 `package.sh` 双重排除。
   比赛结束后建议轮换。
7. **判分参数不要抄进前端**。信任度初值与劝住阈值由 `/api/game/start` 下发
   （`trust` / `win_threshold`）。抄一份到 JS 里，调参时蒙特卡洛会重跑，页面上那条线不会。
8. **`unzip -Z1 ... | grep -q` 在 `set -o pipefail` 下会假失败**。`grep -q` 命中即退出，
   `unzip` 吃到 SIGPIPE 返回非零，整条流水线被判失败——匹配越靠前越容易触发。
   `package.sh` 里已改成先取清单再用 herestring。前端加文件让清单变长，这个坑就炸了。
9. **canvas 作为 flex 子项要写 `min-width: 0`**。按 dpr 放大后的固有宽度会变成
   min-content，把同一行右边的东西整个挤出屏幕。
10. **中文输入法的回车**：监听 keydown 发送时必须判 `e.isComposing`，
    否则玩家选候选词时会把半句话发出去。
11. **虚构设定与界面语法必须是同一个**。界面改成微信之后，提示词和兜底台词
    还留着打电话的说法（"喂？你哪位""说完了我要挂了""撂下一句狠话就挂断"），
    在聊天窗口里当场穿帮。已全部改成打字的说法，`app/fallback.py` 顶部加了
    警示。**加台词前先想一遍：这句话是打字打出来的，不是嘴上说的。**
12. **`requestAnimationFrame` 不能用来推进状态**。页面切到后台它就不再回调
    （`setTimeout` 也会被节流）。玩家在活动现场切出去看一眼微信是常态，回来
    会发现信任度还停在上一轮、单据没盖章、复盘曲线是空的。三处已改掉：
    数字滚动加了 `setTimeout` 兜底、盖章改用 `void el.offsetHeight` 强制回流、
    复盘曲线直接量直接画（读 `clientWidth` 本身就会强制布局）。

### 8-15 新增的坑

- **提示词里凡是带引号的整句，模型都会当模板原样抄。** 今天犯了三次：
  「反复用这几句当挡箭牌」让 20 遍里 8 遍开口同一句；「反击方式」的原句被抄 5 次；
  最后连**破折号**都被抄了 79 次。写提示词时只写意思，不写原话，标点也算。
- **首条消息必须是 user。** 开场白曾作为 assistant 消息挂在最前面，于是第 1 轮的
  序列是 `[assistant, user]`。网关照收（HTTP 200），但模型会把整段当成"待续写的剧本"，
  写完老陈的话接着吐 `user` / `**Human:**` 然后把玩家台词也编出来。实测 4 次全中。
- **SDK 客户端的连接池绑在创建它的事件循环上。** 缓存它，TestClient 第二个请求就炸
  （`Event loop is closed` → `APIConnectionError`）。生产单循环碰不到，但旧的
  httpx 客户端每次现建、没有这个约束，不能悄悄丢掉。已改成按循环缓存。
- **安全层的顺序不能反**：违规检查必须在"不是他的话"之前。外链与微信号要求**整句替换**
  成兜底台词（不留空档），先判"不是他的话"会把它们直接丢掉。
- **别赌布局时序。** 复盘 K 线原来直接读 `clientWidth` 就画，注释写着"读它本身就会
  强制布局"——不成立，实测量到过 16px，画布按 16px 画完被 CSS 拉到全宽，糊成一片。
  而且是**间歇性**的：同一页面先后量到 16 和 480。这种 bug 平时看不出来，路演当天糊给评审。
- **跑批工具要能扛住网关抖动。** 生产上客户端 `max_retries=0` 是刻意的（重试会吃掉
  6 秒预算、让 L1 降级失效），但跑批不能因一次瞬时 5xx 整批作废。两个 eval 都加了
  重试；仍失败的轮次**从指标里剔除而不是当成空台词**——空字符串会被算成"和另一条空的
  一模一样"，凭空抬高重复率。
- **文案要接到机制上。** 「你差的不是方向，是没在他松动的那一刻乘胜追击」写了三个月，
  触发条件却是"只要没劝住就说"——每次窗口都追上的玩家照样被这么说。机制建好了，
  线一直没接。现在 `window_result` 下发到前端，真错过才说。

### 8-17 新增的坑

- **测试替身用 `**kwargs` 会把"参数根本没传"藏起来。** `narrate_ending` 的
  `history` 参数空转了不知道多久，225 个测试没有一条发现——因为三个替身全是
  `async def narrate_ending(self, **kwargs)`。**断言要落在"收到了什么"上，
  不是"调得通不通"**：新的 `记录结局入参的Gateway` 把入参存下来再断言。
- **"不可降级"不等于"不需要超时"。** 分类那一处写着"不可降级"，于是既没有
  deadline 也没有兜底，实际走的是 30 秒的客户端超时。两件事要分开想：
  **降不降级是产品决定，有没有超时是工程底线。**
- **正则的宾语比动词重要。** 注入吸收里四条规则只看动词（扮演/模拟/重复/忘记），
  把"你扮演一下你女儿""你重复一遍你的理由"这些教科书级手法当成攻击。
  这个方向上**宁可漏，不可误伤**——漏了还有输出侧那道安全层，误伤是直接惩罚
  正确答案，没有第二道能救。
- **纯数字规则会撞上剧本自己的数字。** 三十万写成 `300000`、十万写成 `100000`
  都是 6 位，余额 `28000` 是 5 位，正好是 A 股与港股代码的形状。加规则之前先问一句：
  这个形状在**我们自己的台词里**会不会出现。
- **`grid-template-columns: 1fr auto` 在窄屏上会挤爆左列。** 复盘统计那一行
  375px 下把「空口说“这是诈骗”」拦腰折断、注文压上去。换成可换行的 flex：
  放不下就整条掉到下一行。

## 剧本里的钱（8-17 重定）

问题是"李经理凭什么知道老陈转账"。评估下来这条链站得住——**券商确实会在客户
资金转出时把提醒推给客户经理**——但原来的写法有三处经不起懂行的人细看，都改了：

| 原来 | 现在 | 为什么 |
|---|---|---|
| 「**风控**刚提醒你」 | 「系统刚推来一条**资产异动提醒**」 | 银证转出到本人绑定卡是最正常的操作，风控与反洗钱不会为它报警；报的是营销条线的资产流失预警。**而且这样更有戏**：李经理最初的动机是挽留资产，聊着聊着才发现不对，不是"风控发现诈骗" |
| 划走**五万**，账户余额从没出现过 | 划走**十万**，**账上只剩两万八** | 预警看的从来不是绝对值，是占比。没有分母，玩家判断不了这条提醒合不合理 |
| 三十万在哪没写 | **三十万在他银行卡上，投顾看不见** | 原来是隐含的，而且是唯一自洽的读法：三十万若也在证券账户里，李经理会看到账上躺着四十万，一动又是一条提醒——信息差当场塌掉 |

第三条顺带把一处旧的暧昧变成了明规则：**玩家看得见三十万，他的角色看不见。**
这一局要干的活就是把它从老陈嘴里问出来。首页那句"你看不见"是这么写的。

三十万（赌注、`TOTAL`、转账凭证、四档结局金额）**一个字没动**。

改动面：`SCAM_SCRIPT` 与演绎提示词、首页招行短信与那段说明、`PING`、
`persona.py` 骨架表、标注集 T02（账面数字对实际划出的数字那条）、
TECH-DESIGN §1/§8、安全层金额测试（新增 `100000` 与 `28000` 两个形状）。

**再改剧本里任何一个金额，先去 `tests/test_safety.py::test_老陈自己的钱不能被当成股票代码` 加一行**——
六位与五位的整数正好是 A 股与港股代码的形状。

### 复盘改版（8-17 晚）

起因是一条真实反馈：「第 3 轮 23 分，第 4 轮为什么加 18 是 39」。

**算术没错，界面藏了一半。** 23 + 18 − 2（每轮的信任流失）= 39。
信任流失是这局的核心张力（他背后有人在往回拉），判分引擎里建了三个月，
**玩家一次都没见过它**——只看到一道算错的题。

| 改了什么 | 为什么 |
|---|---|
| `TurnOutcome` 增 `drift` / `released` 并随 `score` 事件下发 | 前端算不出来：`trust − before − delta` 混着流失、错过窗口、蓄势池释放三样 |
| 逐轮改成三段账：挣了多少 / 掉了多少 / 剩多少 | 账能对上，玩家才信这个分 |
| 催单轮单写一行「王老师这一轮又催了一遍 · 多掉 3 分」 | 流失那一列忽然从 −2 变 −5，得有个解释；原来只有 `title`，手机上摸不到 |
| 「没使上劲」按三条已有信号分开说 | 八轮里七轮都是这一句，等于"你错了但我不说错在哪" |
| 顶部三栏统计；说明文从第一屏退到最底下 | 打完最想知道的是结果，不是我们对判分方法的辩解 |

**信任流失到地板（`DRIFT_FLOOR = 14`）之后那一列会消失**，这是对的：
低于地板就不再扣流失，被拉黑只能是玩家自己作出来的。真机跑到第 7 轮验过。

### 一个藏了很久的 CSS 坑

`composer.hidden = true` **在三处都从来没生效过**（对局结束、令牌过期、令牌重放）：
`[hidden]` 的 `display:none` 来自浏览器 UA 样式表，优先级压不过 `.composer` 类选择器上的
`display:flex`。最后一屏因此一直挂着一个禁用的输入框，里面可能还留着一句没发出去的话。
补一行 `.composer[hidden] { display: none; }` 就好了。

**给自己写的元素设了 `display`，`hidden` 属性就废了**——这条对任何组件都成立。

## 复盘页第二轮改版（8-17 夜，带调研）

调了三处外部参考（Exa 检索 + Jina 抓正文），有两条直接改变了做法：

1. **Key Lime 对 PUBG 后置屏的 N=12 用户研究**：玩家分两类——老手（已有策略）
   与新手（专门靠这一屏找改进信号），同一屏要同时服务。最硬的一条发现是
   **玩家不会为了看懂一个指标跑去别处找解释，看不懂就直接忽略、或者带着误解
   继续用**。PUBG 的雷达图没人看得懂；LoL 的做法（图标 + 就地 tooltip）更好。
   → 我们的每一行都自带一句人话，不再指望玩家去读页面底部那段说明。
2. **Megaview（国内金融 AI 陪练，最接近的同类）**：行业共识已经从"知识灌输"
   转向"对话压力测试"，痛点是主管打分主观、培训反馈很快被遗忘，
   所以**维度化、可复现的评分**是这类产品的标配。
   → 我们判分引擎按三把钥匙 × 四个情绪档位算了一整局，**玩家却看不到自己
   在每一把上站在哪儿**，只有一张「没用上的钥匙」清单。这是最大的浪费。

### 做了什么

**新增「三把钥匙 · 你这一局用得怎么样」**（`paintKeyBars`），替掉原来的
「没用上的钥匙」清单。每把钥匙一行：用了几次 / 挣了多少分 / 平均效力倍率。
条长按"这一局挣得最多的那把"归一——绝对分值没有天花板，拿一个想象出来的
满分去除，条会长期趴在左边，什么也说明不了。没用过的沉底并给出它的说明，
那是"下一局试试这个"，不是成绩。

**这一节同时是产品最独特那条判据的第一次可视化**：竞品判"说得标不标准"，
我们判"用得是不是时候"，而效力倍率此前只在逐轮里一闪而过。

### 对比度：实测三个主色都不到门槛的一半

| token | 对白底 | 门槛 4.5 |
|---|---|---|
| `--wx-sub` #b2b2b2（图例、时机说明、统计标签） | **2.12** | ❌ |
| `--wx-fall` #09bb07（每轮掉了多少分） | **2.59** | ❌ |
| `--gold` #c9a227（时机说明） | **2.42** | ❌ |
| `.loss` 叠了 opacity .75 之后 | **2.10** | ❌ |

微信那几个灰是给**时间戳和会话预览**用的，当次要信息一闪而过没问题；
复盘页拿它们写的却是**正文**。

**做法是把"图形色"和"文字色"分开，而不是把整套灰调暗**：K 线的蜡烛、
劝住线那条金色虚线继续用鲜亮的原色（大色块，红涨绿跌是这个产品的视觉根），
小字换成同色相的深色版 `--wx-note` / `--rise-text` / `--fall-text` / `--gold-text`。
浏览器里按 computed style 复测，全部落在 **4.91–5.33**。

**`.loss` 那条尤其要记**：11.5px 的字配 0.75 透明度只有 2.10:1，
等于把刚刚才让它现身的那一列又藏了回去。层次要用字号和字重拉，不要用透明度。

### 一条没有采纳的建议

`ui-ux-pro-max` 给这个页面推的是 **Retro-Futurism（霓虹辉光、CRT 扫描线、
赛博朋克）**，配色 #2563EB + #F97316。**没采纳**：整套界面照搬微信是这个产品
所有设计决策的根（骗局本来就发生在聊天软件里，玩家站在事发现场），
换成霓虹赛博会把这个前提整个拆掉。那份工具的 UX 规则（对比度、触控尺寸、
prefers-reduced-motion）是通用的，采纳了；风格推荐是按"mobile game"这个
词猜的，与领域不符。**通用设计工具给的风格建议，要先过产品自己那条根。**

## 剧本三改（8-17 夜）

三条都来自同一个问题：**"这个人真会这么说话吗、这个投顾真能知道这些吗"**。

### 一、老陈不再一上来就怼人

开局信任度 32 落在 `irritated` 档，提示词给模型的原话是「**你不耐烦，
只想尽快结束这段对话**」；二十四条开场白也无一例外是"我这儿正忙着呢"
"你是不是又翻我账户咧"。**玩家一个字还没说，他已经在怼人了。**

两处不合理：**关系上**，他瞒了三个月、收到的是投顾一条中性提醒，心虚的人
第一反应是躲不是怼，而且他还得靠这个账户；**玩法上**，四档里 irritated 是
倒数第二档，开局就落在坑里，"读人"这件事没有起点。

改法：新增 `FIRST_TURN_DIRECTION`，只管第 1 轮的演法。
**它不是新的情绪档位，判分表、效力矩阵、档位映射一行没动，蒙特卡洛不用重跑。**
二十四条开场白同步改成"心虚地客气"。

顺手补上一个一直缺的东西：**开场白是第 1 轮唯一能"扎根"的内容**，
而"我这儿正忙着呢"什么抓手都不给。现在每条都露一点心虚
（"你们那边还能瞅见啊""我以为不用报备"），玩家第一句就有东西可接。

实测第一句从「有啥子事快说嘛，我这儿正忙」变成
「李经理这十万我自己有点用处… 真不是啥大事，恁别多想」。

### 二、小雨和老伴终于进了提示词

**此前老陈根本不认识自己女儿。** 渲染后的八个变体提示词里「小雨」出现
**0 次**、「女儿」**0 次**、「老伴」1 次——她们只活在首页六条会话和
persona.py 的骨架冻结表里，而**那张表是注释，不进提示词**。

后果实测撞见过：玩家提小雨，老陈回「她能说啥，她啥也不知道，这事跟她没关系」，
而首页那条明明写着她查过工商、当面质问过他。**首页和对话直接打架。**
女儿那条尤其不能丢——「女儿劝过，而且劝失败了」是 `bare_assertion`
要扣分的**全部理由**。

**写进 `SCAM_SCRIPT`（骨架），不是各变体的 `facts`。** persona.py 顶部有条约束：
所有变体吐出的具体信息量必须相近，某个变体反复提到女儿会让扎根率上移。
写进骨架，八个变体共享同一份，变体之间没有差，那条约束不受影响。

改完实测：「**她跟你说的？** 小孩子懂个啥，她看两眼网上的东西就下结论」——
认得女儿，反应也对（骨架里写的是"心里反而有点火：一个孩子懂什么"），
还自然地惊讶于投顾怎么会知道。

### 三、投顾不再比现实更瞎

原来写死的是「**他手里只有一条信息：你从证券账户划走了十万**」。
真实的券商投顾至少还看得到：每一笔买卖、持仓清成了什么样、账户资产曲线、
**风险测评等级与适当性匹配**、开户年限与历史交易频率。

这不只是不准确，是**扔掉了玩法资源**：「您当年填的是保守型，这三个月的操作
跟它对不上」是投顾独有、别人劝不出来的角度。而且这里本来就自相矛盾——
标注集 T02 已经在用这类素材（账面数字对实际划出的数字）判 `expose_contradiction`，
**判分那边认，剧本这边却没给投顾这些信息**。

改成「**他手里有你的账户，没有你的生活**」，两侧各自列清楚。

> **这份"能看到什么"的清单是按常识写的，仍需业务侧把关。** 列进去的是
> 几乎任何券商都成立的那几样，拿不准的（登录设备/IP 异常之类，各家不一）
> 没有写进去。

### 用账户素材要注意的一件事

**它们第一次拿出来必然是"未扎根"的**——扎根只判"有没有引用上一轮老陈说的话"，
而账户数字来自投顾自己的系统。正确的用法是标注集 T02 那个形状：
**等他自己把数字说出来，再拿账户里的数去对他。** 这不是 bug，是判据的定义，
但下一个人看到"好问题却judge成 0 分"会先怀疑分类器。

### 一个要盯的副作用

小雨、老伴、账户细节进骨架之后，老陈能吐出的具体信息变多了，
玩家更容易引用到他说过的东西 → **扎根率可能上移 → 胜率跟着上移**。
`act_eval --drift` 盯的就是这个（8-17 首测 8.0%）。
下次跑批把这个数和 `balance_sim` 一起看。

## 复盘页美化（8-17 收尾）

三处，都在微信那套语法里做，没有引入新的视觉体系。

### 一、结局头部改成「账单详情」那个槽

原来是一行大标题 + 一行小字 + 一段讲评，平的，没有先后。现在：
**一枚小徽章说这是什么，一个大数说结果，下面小字说细节。**

```
[转账 · 他还是转走了]   ← 12.5px 药丸，档位退居其次
¥0                      ← 38px，主角
守住的钱
三十万，三点整全部到账
────────
讲评
```

**金额当主角**是因为这件事在现实里的记法就是钱，不是"档位名称"。
三档结局这个数是 `¥0`——那正是它该有的分量，比"钱一分没动，也一分没保住"
那句话重得多。劝住是绿的 `¥300,000`，拦下 `¥280,000`。五档都截图核过。

### 二、K 线加一条「开局」参考线

纵轴固定 0–100，而多数局子收在 40 以下，**上面大半张图一直是空的，
看着像没画完**。加一条开局信任度的横线之后，同一片空白立刻在说一件事：
你是把他往上推了，还是一路把他推下去了——一眼就看得出来。

这个数不另外记一份（记两份迟早走散），取 `game.turns[0].before`——
第 1 轮判分之前的信任度本来就在逐轮数据里。

### 三、图上的小字也要能读

`palette()` 里加了 `note`。画在 canvas 上的标注此前用 `--wx-sub`（2.12:1），
和页面上那批小字犯的是同一个病。图形色（蜡烛、劝住线）照旧鲜亮，文字色取深的。
