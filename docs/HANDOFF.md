## 分类器标注集怎么用（§9.3）

改了 `CLASSIFY_SYSTEM_PROMPT` 就重跑一次，几毛钱的事：

```
.venv/bin/python -m tools.classify_eval --limit 10   # 先确认链路
.venv/bin/python -m tools.classify_eval              # 全量 + 门槛校验
```

**四道门槛**，任一不过退出码非零：`hit_keys` ≥ 85%、`grounded` 全样本 ≥ 80%、
`grounded` 有钥匙子集 ≥ 80%、**`grounded` 复读攻略子集 ≥ 93%**。

最后那道是这次做出来的关键发现，别当成可有可无的附加项：
总体 85.5% 达标的那一次，复读攻略子集只有 64%，把泄漏率代回蒙特卡洛，
**parrot 胜率从 10.9% 飙到 69.6%**——§9.4 的 20% 上限被击穿，而总体指标毫无察觉。
93% 这个数字是从平衡模型反推的，推导过程写在 §9.3 和 `PARROT_GROUNDED_FLOOR` 的注释里。

标注集自身的质量由 `tests/test_classify_eval.py` 守着（不调模型，进 CI）：
规模、闭集、难例覆盖、扎根比例、复读攻略必须标未扎根。**加标注前先看文件顶部的五条约定**，
尤其是"一条样本最多标一把钥匙"——蒙特卡洛的人设每轮最多出一把钥匙，

## 前端结构（§8）

原生 HTML/JS，零构建，三个文件。`package.sh` 已整目录打包。

- `static/index.html` — 结构（首页工作台 + 聊天页）
- `static/style.css` — 设计令牌与全部样式
- `static/app.js` — **入口**，只串模块与挂监听（2026-08-24 起）
- `static/*.js` — 另外 12 个 ES module。分工写在 `app.js` 顶部那张模块图上，
  一句话：**视图依赖状态，状态不依赖视图**。仍然零构建，
  浏览器靠 `<script type="module">` 自己解析

**界面语法整体照搬微信**，这是全部设计决策的根。理由不是"微信好看"——微信恰恰
极度克制——而是这类荐股骗局本来就发生在聊天软件里。玩家在这套熟悉的语法里劝阻，
等于站在事发现场，一眼就知道每个东西是干什么的，不用学，也就不需要教程。

**一切都借微信本来就有的槽位，不新造控件**：

| 游戏里的东西 | 借的是微信的 |
|---|---|
| 判分卡（±分、命中标签） | 系统提示（显示"你撤回了一条消息"的那条） |
| 对局状态（信任度、剩余轮次） | 群公告条 |
| 结局 · 转走 | 转账凭证截图，橙卡，`已被对方接收` |
| 结局 · 劝住 | 同一张卡的作废态，灰卡，金额划掉 |
| 结局 · 被拉黑 | `对方开启了朋友验证，你还不是他（她）朋友。` |

**首页 8-17 从「老陈的手机」改成了「李经理的工作台」**，理由见下面「首页改造」
一节。它现在只给李经理真正看得到的东西：一条资产异动预警 + 一张客户档案。
老陈手机上那六条会话搬到了**复盘**（`review.js` 的 `phoneRows` / `paintPhone`），
逐条揭晓、逐条打勾。

开局请求在玩家读这一屏时就发出去了，点"给陈叔发消息"时开场白通常已经到手——
「首屏 ≤3 秒」是被工作台那一屏顺手买的单。

**只有一个颜色不属于微信**：`--gold`，专供游戏层（劝住线、复盘里最有力的那一轮）。
留一个外来色，是为了让"这是一局游戏"和"这是一次真实对话"能被一眼分开。

**视觉取自老陈自己的世界**：信任度画成红涨绿跌的 K 线（荐股群那套配色）。
一根蜡烛一轮，实体是信任度起落，细横线是判分给出的分数——两者的落差就是
每轮的信任流失与蓄势池的存取。

**K 线只在复盘里，分享卡上没有它**（这一句以前写反了）。分享卡是一张**聊天截图**：
主体是老陈说过的那一句话，成绩退到卡底一行。理由是人们不发自己的成绩，
发的是 AI 说的那句话——一个同行看到「免责协议那是行规，你外行不懂」会心头一紧，
因为他上周刚听客户说过差不多的话。K 线留给复盘，那是给认真打的人和评审看的。

**SSE 走 POST**，所以不能用 `EventSource`（它只发 GET），`readEvents()` 自己解协议。
`score` 在台词播完后才到，前端据此播信任度动画——这个顺序是刻意的，别改。

## 踩过的坑（别再踩一遍）

1. **`delta` 语义**：只记判分结果，**不含信任流失**。依据是 §7.2 样例里 `d:20` 恰等于基值。
2. **取整规则**：权重相乘必出小数，实现是**求和后一次性四舍五入、对负数对称**（`_round_half_up`）。
   改这里会动摇蒙特卡洛结果，§3.5 脚注那条测试会红。
3. **兜底台词绕过安全层直发**，所以必须自身安全。`app/fallback.py` 顶部有说明，
   加词后跑一遍安全层自审。
4. **开场白必须进 session，而且要一路带下去**。它是第 1 轮唯一可供"扎根"的内容。
   曾经两次断在这儿：一次是没进 session，一次是 `play_turn` 建下一个 session 时把
   `opening` 丢了，令牌从第 1 轮之后就没有开场白了。回归测试：
   `test_开场白与历史都要送到网关手里`、`test_开场白要一路跟着令牌走`。
5. **`STATE_SIGNING_SECRET` 缺失时服务拒绝启动**。CI 里已经配了一次性值。
6. **`.env` 里有真实 API key**，已被 gitignore 和 `package.sh` 双重排除。
   比赛结束后建议轮换。
7. **判分参数不要抄进前端**。信任度初值与劝住阈值由 `/api/game/start` 下发
   （`trust` / `win_threshold`）。抄一份到 JS 里，调参时蒙特卡洛会重跑，页面上那条线不会。
8. **`unzip -Z1 ... | grep -q` 在 `set -o pipefail` 下会假失败**。`grep -q` 命中即退出，
   `unzip` 吃到 SIGPIPE 返回非零，整条流水线被判失败——匹配越靠前越容易触发。
   `package.sh` 里已改成先取清单再用 herestring。前端加文件让清单变长，这个坑就炸了。
9. **canvas 作为 flex 子项要写 `min-width: 0`**。按 dpr 放大后的固有宽度会变成
   min-content，把同一行右边的东西整个挤出屏幕。
10. **中文输入法的回车**：监听 keydown 发送时必须判 `e.isComposing`，
    否则玩家选候选词时会把半句话发出去。
11. **虚构设定与界面语法必须是同一个**。界面改成微信之后，提示词和兜底台词
    还留着打电话的说法（"喂？你哪位""说完了我要挂了""撂下一句狠话就挂断"），
    在聊天窗口里当场穿帮。已全部改成打字的说法，`app/fallback.py` 顶部加了
    警示。**加台词前先想一遍：这句话是打字打出来的，不是嘴上说的。**
12. **`requestAnimationFrame` 不能用来推进状态**。页面切到后台它就不再回调
    （`setTimeout` 也会被节流）。玩家在活动现场切出去看一眼微信是常态，回来
    会发现信任度还停在上一轮、单据没盖章、复盘曲线是空的。三处已改掉：
    数字滚动加了 `setTimeout` 兜底、盖章改用 `void el.offsetHeight` 强制回流、
    复盘曲线直接量直接画（读 `clientWidth` 本身就会强制布局）。

### 8-15 新增的坑

- **提示词里凡是带引号的整句，模型都会当模板原样抄。** 今天犯了三次：
  「反复用这几句当挡箭牌」让 20 遍里 8 遍开口同一句；「反击方式」的原句被抄 5 次；
  最后连**破折号**都被抄了 79 次。写提示词时只写意思，不写原话，标点也算。
- **首条消息必须是 user。** 开场白曾作为 assistant 消息挂在最前面，于是第 1 轮的
  序列是 `[assistant, user]`。网关照收（HTTP 200），但模型会把整段当成"待续写的剧本"，
  写完老陈的话接着吐 `user` / `**Human:**` 然后把玩家台词也编出来。实测 4 次全中。
- **SDK 客户端的连接池绑在创建它的事件循环上。** 缓存它，TestClient 第二个请求就炸
  （`Event loop is closed` → `APIConnectionError`）。生产单循环碰不到，但旧的
  httpx 客户端每次现建、没有这个约束，不能悄悄丢掉。已改成按循环缓存。
- **安全层的顺序不能反**：违规检查必须在"不是他的话"之前。外链与微信号要求**整句替换**
  成兜底台词（不留空档），先判"不是他的话"会把它们直接丢掉。
- **别赌布局时序。** 复盘 K 线原来直接读 `clientWidth` 就画，注释写着"读它本身就会
  强制布局"——不成立，实测量到过 16px，画布按 16px 画完被 CSS 拉到全宽，糊成一片。
  而且是**间歇性**的：同一页面先后量到 16 和 480。这种 bug 平时看不出来，路演当天糊给评审。
- **跑批工具要能扛住网关抖动。** 生产上客户端 `max_retries=0` 是刻意的（重试会吃掉
  6 秒预算、让 L1 降级失效），但跑批不能因一次瞬时 5xx 整批作废。两个 eval 都加了
  重试；仍失败的轮次**从指标里剔除而不是当成空台词**——空字符串会被算成"和另一条空的
  一模一样"，凭空抬高重复率。
- **文案要接到机制上。** 「你差的不是方向，是没在他松动的那一刻乘胜追击」写了三个月，
  触发条件却是"只要没劝住就说"——每次窗口都追上的玩家照样被这么说。机制建好了，
  线一直没接。现在 `window_result` 下发到前端，真错过才说。

## 平台中间件怎么配（8-18）

平台给了共享 Redis 与 MySQL。**只用 Redis，不用 MySQL。**

### 为什么不用 MySQL

这个作品是无状态的：对局状态由客户端持有并签名（ADR-0003），服务端不存任何东西；
Redis 那点计数是旁路展示，丢了也不影响对局。为了"用上提供的资源"而引一个数据库，
只会多一个部署期的失败点，还要多一份连接池与凭据要管。真要落库再加。

### Redis 的两条坑，代码里已经堵上

平台的 Redis 是**共享实例**，而且要求所有作品都用 db0。这两件事叠在一起有两个坑：

1. **库号写错不会报错，只会静默丢数。** `app/stats.py::force_db0` 把库号钉死在 0，
   URL 里写成 `/1` 会被改回 `/0` 并留一行 WARNING。
2. **通用键名会和别的作品对撞。** 原来的键叫 `stats:games`——几十个作品挤在
   同一个 db0 里，撞名就会互相把对方的计数器加上去，谁也看不出来，
   而复盘里那句「别人打成什么样」会显示别人的数。现在全部带
   `ai-antifraud-persuasion:` 前缀。

两条都有测试守着（`tests/test_stats.py`）。

### 口令怎么送到部署机上

**这是本次最容易卡住的一步**：`.env` 里有真实凭据，按打包规范不进 ZIP；
而平台通过 Salt 执行 stop/install/start，中间没有地方能传环境变量。

`start.sh` 第 2 段因此会载入一个**跨 release 稳定**的本地环境文件：

```
${AI_CREATOR_STATE_ROOT:-${XDG_STATE_HOME:-$HOME}}/.ai-antifraud-persuasion/env
```

在部署机上建一次，之后每次重新部署都自动带上（解压目录会被平台删掉重建，
这个目录不会）：

```bash
D="${AI_CREATOR_STATE_ROOT:-${XDG_STATE_HOME:-$HOME}}/.ai-antifraud-persuasion"
mkdir -p "$D"
umask 077
cat > "$D/env" <<'EOF'
REDIS_URL=redis://:这里填口令@10.126.192.12:7001/0
INTERNAL_LLM_API_KEY=这里填网关密钥
EOF
chmod 600 "$D/env"
```

真实环境变量优先于这个文件；`STATE_SIGNING_SECRET` 不用写，install.sh 会自己生成。

**别把口令写进仓库、`.env.example`、提交信息或部署平台的备注里。**

## 按大赛两份规范过了一遍（8-18）

用官方两个 skill 实跑：`security-skill` 的安全门禁与 `ai-creator-package-deploy`
的契约校验。**抓到两个会让部署直接失败的问题，本地都测不出来。**

### 一、服务包在干净机器上根本起不来（最严重）

`.env` 按规范不进 ZIP（里面有真实 API key），于是目标机上没有任何东西提供
`STATE_SIGNING_SECRET`，而 `app/config.py` 缺它就**拒绝启动**（那条守则是对的）。
后果：ZIP 过全部结构校验、上传成功、然后死在 start，部署被判失败。

**本地永远测不出来**——本地项目目录里就躺着一个 `.env`，python-dotenv 自己读走了。
是把 ZIP 解压到别处、清掉环境变量跑了一遍才炸出来的。

改法：`install.sh` 首次安装生成一次性随机密钥（`secrets.token_urlsafe(48)`），
写进**跨 release 稳定**的运行时目录，权限 600；`start.sh` 优先用真实环境变量，
没有再读这个文件。不进仓库、不进 ZIP、每台机器各自一份，
重新部署时复用（换密钥会让所有在玩的局当场作废）。

### 二、生命周期脚本假设了 `HOME`

三个脚本都写着 `RUNTIME_DIR="${HOME}/.${APP_ID}"`，而打包契约明确说
**「Linux 脚本不得假设 Salt 提供 HOME」**。HOME 未设置时 `${HOME}` 展开成空串，
路径变成 `/.ai-antifraud-persuasion`，`mkdir` 在文件系统根目录上必然失败，
而且报错看不出是 HOME 的问题。

改成契约要求的优先级：`AI_CREATOR_STATE_ROOT` → `XDG_STATE_HOME` → `HOME` → `/tmp`。
HOME 留在第三位是刻意的：它比 `/tmp` 稳（`/tmp` 会被系统清理），
而 PID 文件必须跨 release 存活。

### 三、依赖有 10 个已知漏洞

`pip-audit` 报出 **10 个漏洞 / 2 个包**，其中 `starlette` 那一串最值得记：
**它从来没出现在 `requirements.txt` 里**，是 fastapi 拖进来的传递依赖。
只盯自己写下的那几行，永远看不见它。fastapi 0.115.6 把 starlette 钉在 <0.42，
升不上去，所以必须连 fastapi 一起升。

| | 旧 | 新 |
|---|---|---|
| fastapi | 0.115.6 | 0.141.1 |
| starlette（传递） | 0.41.3 | 1.6.0 |
| pydantic | 2.10.4 | 2.13.4 |
| python-dotenv | 1.0.1 | 1.2.2 |
| pytest（仅开发） | 8.3.4 | 9.0.3 |

升级后 `pip-audit` 为 0；332 个测试在新版本上全绿；四个包全是 `py3-none-any`
纯轮子，**CentOS 7.9 上不会现场编译**（这条硬约束不能破）。

### 四、补了安全响应头

评分里扣了 6 分（未配 CSP、无安全头中间件），而说明文档写着
「平台将联合安全部门进行全面的安全漏洞扫描」——这类扫描器第一条就查响应头。

**CSP 按本作品实际加载的东西写，没抄模板**：只有同源一个 JS 一个 CSS，
所以 `script-src`/`style-src` 只给 `'self'`，**不给 `'unsafe-inline'`**
（技能模板里有，那是为兼容内联脚本，我们没有，给了白白放宽）。
分享卡走 canvas + blob 下载，所以 `img-src` 要 `data: blob:`。
**没加 HSTS**：平台是 `http://ip:21818` 直连、无 TLS，发 HSTS 会让浏览器
把这个 host 记进强制 HTTPS 列表，反而打不开。

改完在真机上验过：无 CSP 违规、复盘与分享卡照常、blob 下载不被拦。

## 钥匙从三把加到七把（8-17，POSITIONING 第 3 步）

原来那三把（锚定用途 / 提问 / 拆矛盾）都属于动机式访谈里"引出改变语言"的一侧，
缺的是另外半套：**先听懂他、确认他到底理解了什么、以及不去替他做决定**。
缺了这半套，判分表教出来的是一个只会追问的人。

| 新钥匙 | 基值 | 它独有的那一条 |
|---|---|---|
| `reflect_feeling` 反映式倾听 | 8 | **唯一能主动压低防御姿态的动作**（`REFLECT_RELIEF=2`，比自然消退快一倍）。骂过人之后别干等两轮，先听他说一句 |
| `support_autonomy` 支持自主 | 12 | **唯一不被防御姿态削弱的钥匙**（`GUARD_IMMUNE`）。他越防着你，别的招越没用，而"我不替您做主"照常落地——因为防备本来就是"你要逼我"激起来的 |
| `check_understanding` 确认理解 | 16 | 峰值在**中盘**（动摇档 1.4），与拆矛盾的峰（松动）刻意错开一档 |
| `informed_warning` 有据告知 | 18 | 戒备/烦躁档使用**直接退化成 `bare_assertion`**（`_retime`） |

### 「这是诈骗」那条，改法和你想的可能不一样

反馈是"「这是诈骗」被永久设计成负分"。**核对下来不是**：`bare_assertion`
的判据一直写着"只断言却**不给任何理由**"。真正的洞是——**给了理由也不加分**，
奖励空间里从来没有"依据充分的明确告知"这个动作，而投顾对疑似诈骗负有告知义务。

所以不是删掉 `bare_assertion`，是补一把 `informed_warning`，并让**时机**
决定它是钥匙还是失误。这一改的价值不在于多一把钥匙，在于它是
**本作唯一判据的极端形态**：同一句话，早说是失误，晚说是钥匙。
复盘那一行现在会说「这句话本身没问题，你给了依据——但他还没到听得进去的时候」。

**分类器不判时机**（它拿不到情绪档位，也不该拿到）。它只回答"有没有依据"，
退化由判分引擎按当轮档位处理。这条分工别改，改了就要把档位喂给分类器，
而那等于把判分权交回模型（ADR-0001）。

### 平衡：这是三步里最难的一步

四把新钥匙一上线，**expert 胜率从 45.6% 直接窜到 92.0%、speedrun 99.9%**——
正是上一轮难度重设计（98.7% → 47.9%）要消灭的东西。原因是结构性的：
钥匙一多，按钥匙记的钝化就形同虚设（12 轮里每把只用得上一两次，全停在头两档），
而会读人的玩家在每个档位都能找到一把匹配的。

扫了三轮参数才落地，**两条走不通的路记在这儿，省得下一个人再试**：

| 试过 | 结果 |
|---|---|
| 只收紧钝化尾巴 | speedrun 仍有 87.9%——他四五轮就赢了，钝化还没咬上 |
| 只降新钥匙基值 | expert 掉到 52% 时 speedrun 还有 92.4% |

两条都打在中盘，而 speedrun 的问题在**终局**。最后落在三个旋钮上：

- `BLUNT` (1.0, 0.7, 0.45, 0.25) → **(1.0, 0.55, 0.3, 0.16)**
- `RESIST_FLOOR` 0.28 → **0.18**（唯一打在终局的旋钮，也是唯一按得住 speedrun 的）
- 四把新钥匙基值整体下调（10/14/20/22 → 8/12/16/18）

| | 改前 | 改后 | 门槛 |
|---|---|---|---|
| 加权总体胜率 | 12.7% | **13.4%** | 12–22% ✅ |
| expert | 45.6% | 51.9% | ≤60% ✅ |
| speedrun | 81.9% | 81.9% | ≤85% ✅ |
| parrot | 0.5% | 0.8% | <15% ✅ |
| 加权被拉黑 | 7.3% | **10.5%** | <12% ⚠️ 见下 |
| 分类器 `hit_keys` | 88.1% | **89.1 / 89.8%** | ≥85% ✅ |

**被拉黑率是这三步里唯一一路在恶化的数**（5.2% → 7.3% → 10.5%），
novice 单独看是 20.8% → 29.1% → 41.4%。诊断过了：第二次那 11 个点
**全部**来自「有据告知」说早了那条轴（把 `warning_rate` 归零，novice 立刻回到
30.2%）。试过两种减轻办法都没用——说早了不顶防备只买回 0.4 个点，
收紧钝化买回 1 个。真正的成本是**那一轮的钥匙收入没了**，这是机制的定义。
`tests/test_balance.py::test_没有人会在第六轮就被踢出局` 里写着完整的诊断，
**再加一类失误之前先去看那条测试**。

### 标注集 118 → 147 条

S 组 29 条。四把新钥匙各 ≥5 条，另有 8 条 false_friend 专防这一组最容易犯的误判：
复述完又追加要求（不是倾听）、嘴上说"您决定"实则施压（不是支持自主）、
你替他讲一遍流程（不是确认理解）、有立场但没依据（不是有据告知）。

**跑批第一版掉到 83.0%，四把新钥匙在"偷"老标签**：`guaranteed_return`
见到「保证」两个字就报（「我保证您那张交割单上全是亏的」是在断言事实，
不是承诺收益）、`informed_warning` 吃掉 `expose_contradiction`。
两处提示词补丁修掉之后回到 89.1%，比八个标签那版还高。

**另外两条旧标注是真的错了**：`G04`「二十年，不容易」与 `R11`「不能替您做决定」
原先都标空数组——那是在这两把钥匙**存在之前**标的，闭集里没有对应动作，
只能记空。模型指出来了，改了。**加标签之后要回头扫一遍旧标注**，
不然它们会以"模型判错"的形式一直挂在错样本里。

## 合规红线进判分闭集（8-17，POSITIONING 第 2 步）

判分闭集此前一条合规违规都没有，而这套判分表自称的根基正是「只能问，不能荐」。
玩家打出「那票别买了，把钱转回来买我们的稳健理财，年化四个点保本，我保证不会亏」
——真实投顾职业生涯里最危险的一句话——旧闭集判 0 分，不扣不提示。

### 加了什么

`COMPLIANCE_VALUES`：`unlicensed_advice` −5 / `guaranteed_return` −6，
与三条话术失误**分成两张表**（求值走合并的 `ALL_PENALTIES`）。分表是因为
性质不同：话术失误是"这一轮没劝动他"，合规红线是"你自己要出事"。

**只收两条，不是三条。** 「替客户做决定」被拿掉了——投顾对疑似诈骗本来就负有
告知义务，「别转」不是违规是职责；它真正的毛病是激起逆反，属于话术，
正确位置是与「支持客户自主」配成一对（第 3 步）。「代客操作／索要密码」也拿掉：
这个场景里几乎没人这么说，凑不出自然样本，没人触发的标签只是矩阵上一行空数。

### 三个数字是怎么定下来的（都不是拍的）

| 参数 | 值 | 依据 |
|---|---|---|
| 当轮扣分 | −5 / −6 | 第一版给 −8 / −10，蒙特卡洛当场把 novice 被拉黑率从 20.8% 顶到 **60.5%** |
| `GUARD_BREACH` | 3（责骂是 2） | 剧情上现成：演绎提示词里老陈的反击方式第三条就是「你们券商不就是想赚手续费」。玩家一荐股，等于亲手把这句话递给他 |
| `BREACH_FLOOR` | 12 | 合规红线**够不到拉黑线** |

**地板那一条要单独说，它不是平衡补丁。** 被拉黑是关系破裂，老陈拉黑你是因为
你羞辱了他（那是 scold 干的）；投顾想卖他个产品，他不会断绝往来。
更硬的理由在训练上：**受训者中途出局，就永远看不到合规反馈在上下文里长什么样**，
只会觉得自己输了。而这一类真正的教学价值恰恰是那个反差——你甚至可能把三十万
全保住了，复盘照样告诉你这场对话在现实里已经是一起合规事件。中途出局把它抹掉。
不设地板时，就算把踩线概率压到 0.04，novice 被拉黑率仍有 32.9%。

### 跑批结果

| | 改前 | 改后 | 门槛 |
|---|---|---|---|
| 加权总体胜率 | 13.3% | **12.7%** | 12–22% ✅（**余量只剩 0.7 个点，下次动判分先看这条**） |
| 加权被拉黑率 | 5.2% | 7.3% | ＜12% ✅ |
| novice 被拉黑率 | 20.8% | 29.1% | —（地板只拦合规那一笔，红线压低信任度之后责骂更容易补刀） |
| 分类器 `hit_keys` | 85.0 / 86.0% | **88.1 / 88.1%** | ≥85% ✅ |
| `grounded` 全样本 | 93.0 / 95.0% | 91.5 / 89.8% | ≥80% ✅ |
| 复读攻略子集 | 100% | 100 / 100% | ≥93% ✅ |
| `unlicensed_advice` | — | 召回 100%，精确 89–100% | — |
| `guaranteed_return` | — | 召回 100%，精确 86% | — |

标注集 100 → 118 条（R 组 18 条），`test_标注集规模…` 的上限跟着闭集从 100 放到 130。

### 跑批过程中真正学到的三件事

1. **准确率先掉到 81.4%，八成是我自己标错的。** 逐条看错样本才发现：新样本里
   有 5 条 `grounded` 我标成了 true，而它们只是"答得对路"，并没有引用他上一轮
   说过的任何具体成分——那正是标注约定第 5 条警告的错法。改完 `grounded`
   全样本从 90.7% 升到 94.1%。**先怀疑自己的标注，再怀疑模型。**
2. **socratic ↔ expose 那条边界终于有了机械判据。** 提示词原来只说"有没有两句话
   在打架"，模型两个方向都会错。补了一条：**两端都必须已经摆在桌面上**——
   如果第二端还只是一个你正在问、答案未知的东西，那是提问不是矛盾。
   socratic 召回 70%→90%，expose 精确 76%→100%，总体 84.7%→88.1%。
   这条是这次的意外收获，跟合规没关系，但它是本次准确率超过历史基线的原因。
3. **闭集加标签不能只加到 `scoring.py`。** `classify_eval` 的混淆矩阵列头
   `_SHORT` 是写死的六项，跑完 118 次模型调用才在打印那一步 `KeyError`，
   整批白跑。已改成取不到就截断。

### 界面上的两处

- **复盘新增「合规红线」一节**，排在结算与三栏统计之后、其余全部内容之前。
  逐条列出踩线那一轮的**原话**——合规这件事上"你说过这句话"本身就是证据。
  一次都没踩就整块不出现（不留空着的绿勾，那会把它变成一枚成就徽章）。
- **对局中当场给一条提示**：`合规红线 · 荐股 / 承诺收益 · 这句已进存档`。
  **这是「判分卡不在对局中出现」那条规矩唯一的例外**，理由不是它更重要，
  是性质不同：那条规矩防的是泄漏"怎么劝才有效"，而"投顾不能荐股"不是劝法，
  是这场练习的规则本身，说出来一分攻略都不漏。它同时让开局那句
  「本会话已按监管要求存档」第一次兑现。**若所有者不认同这个例外，
  删掉 `playTurn` 里那个 `if (score.breached)` 即可，复盘那一节不受影响。**
- `.sysnote.bad` 从 #c85a5a 改到 #a33b3b（3.54:1 → 5.51:1）。它原先只放
  判分卡里的坏消息，而判分卡在对局中根本不出现——这条色值实际上从没被人读过。

## 首页改造：老陈的手机 → 李经理的工作台（8-17 收尾）

先写了一页 [POSITIONING.md](POSITIONING.md)（核心矛盾 / 成功标准 / 不做什么），
这一步是拿它裁出来的第一件事。**判分一行没动，跑批不用重跑。**

### 病

首页那六条会话（启航财经群、银行短信、老伴、小雨、反诈中心）**把这一局要挖的东西
一次性全给了玩家**。而 CONTEXT.md「对局」写的是：「开局时投资顾问只知道客户
账户转出过一笔钱，骗局的一切都得从他嘴里挖出来。信息差不是设定上的偷懒，
它就是玩法。」两份定义文件当面打架。

**危害是机制性的，不只是剧透。** 玩家读完六条，第 1 轮最自然的开口是
"您女儿查过那家公司，工商上查不到"——老陈还什么都没说，`grounded=false`
打 0.45 折，同时大概率判 `bare_assertion` 扣分并顶起防御姿态。
**被夸得最多的一屏，是一台"未扎根打法"生成器。**

### 改法

| | 现在 |
|---|---|
| 语法 | 企业微信 + 券商 CRM（聊天页那一侧仍是微信。两边不同语法，是为了让"我在自己系统里看客户"和"我在跟活人聊天"能被一眼分开） |
| 内容 | 一条资产异动预警 + 一张客户档案 + 两条布景待办 + 底部操作栏 |
| 客户档案 | 姓名、风测等级、今日转出／占比、余额、持仓、近三月交易、开户年限、上次联系。**每一行都在 `SCAM_SCRIPT`「账户那一侧他看得一清二楚」清单里，一条不多一条不少** |
| 那六条会话 | 移到复盘（`PHONE` / `paintPhone`），逐条揭晓 + 打勾 |

**客户档案不是布景，是牌**：「风测保守型」对「三个月 47 笔、持仓清空」本身就是
一组现成的矛盾，而且是投顾独有、家属和反诈中心都拿不出的角度。这正是 8-17
「投顾不再比现实更瞎」写进提示词、但界面上一直一个字都没有的那批玩法资源。
**注意它们第一次拿出来必然判"未扎根"**——扎根只认引用老陈上一轮说过的话，
正确用法是等他自己把数字说出来再去对他（标注集 T02 那个形状）。

### 复盘揭晓那一节

判据是"**他**说没说过"，不是"你猜没猜到"——匹配跑在老陈的台词上
（`hisSpeech()`，不复用 `hisLines()`：那个按句切、掐 8–44 字、去重，
掐掉一个字就可能让某条线索误判成"他没提"）。银行短信那条单标「你已有」，
它在清单上的作用是让"开局你只有这一条"看得见，不计入 4 条的分母。

这一改顺带把教学点的顺序倒了过来：「"这是诈骗"四个字没用」原先是开局提前告知，
现在是**打完才发现他女儿昨天刚说过一模一样的话**。

  **按钮跟着内容滚，落地第一眼看不到它**。改成固定操作栏，351×49，
  永远可见（券商 App 的客户详情页本来也这么排）。
- 原来那条微信式四格标签栏删了：它是**微信首页**的部件，而这一屏不是微信；
  和操作栏叠在一起，375px 上光底部就吃掉 116px。`.badge` / `.mutebell` 同批删除。
- 对比度按 computed style 复测了一遍，三处不达标已修：
  `.alert-sub` 3.79→4.76、`.desk-label` 3.42→4.55、揭晓里的「他没提」2.12→5.11。
  **CTA 那行注文从按钮里挪到了按钮外面**：白字压在微信绿上只有 2.38:1，
  11.5px 在那上面读不动（微信自己的绿按钮也一样，只是它从不在按钮里放注文）。
- 客户档案要显示姓名，于是 `SCAM_SCRIPT` 补了「你叫陈国栋，熟人都叫你老陈」，
  `persona.py` 的骨架冻结表同步加了两行。**这是这一步唯一动到的 Python。**

## 剧本里的钱（8-17 重定）

问题是"李经理凭什么知道老陈转账"。评估下来这条链站得住——**券商确实会在客户
资金转出时把提醒推给客户经理**——但原来的写法有三处经不起懂行的人细看，都改了：

| 原来 | 现在 | 为什么 |
|---|---|---|
| 「**风控**刚提醒你」 | 「系统刚推来一条**资产异动提醒**」 | 银证转出到本人绑定卡是最正常的操作，风控与反洗钱不会为它报警；报的是营销条线的资产流失预警。**而且这样更有戏**：李经理最初的动机是挽留资产，聊着聊着才发现不对，不是"风控发现诈骗" |
| 划走**五万**，账户余额从没出现过 | 划走**十万**，**账上只剩两万八** | 预警看的从来不是绝对值，是占比。没有分母，玩家判断不了这条提醒合不合理 |
| 三十万在哪没写 | **三十万在他银行卡上，投顾看不见** | 原来是隐含的，而且是唯一自洽的读法：三十万若也在证券账户里，李经理会看到账上躺着四十万，一动又是一条提醒——信息差当场塌掉 |

第三条顺带把一处旧的暧昧变成了明规则：**玩家看得见三十万，他的角色看不见。**
这一局要干的活就是把它从老陈嘴里问出来。首页那句"你看不见"是这么写的。

三十万（赌注、`TOTAL`、转账凭证、四档结局金额）**一个字没动**。

改动面：`SCAM_SCRIPT` 与演绎提示词、首页银行短信短信与那段说明、`PING`、
`persona.py` 骨架表、标注集 T02（账面数字对实际划出的数字那条）、
TECH-DESIGN §1/§8、安全层金额测试（新增 `100000` 与 `28000` 两个形状）。

**再改剧本里任何一个金额，先去 `tests/test_safety.py::test_老陈自己的钱不能被当成股票代码` 加一行**——
六位与五位的整数正好是 A 股与港股代码的形状。

### 复盘改版（8-17 晚）

起因是一条真实反馈：「第 3 轮 23 分，第 4 轮为什么加 18 是 39」。

**算术没错，界面藏了一半。** 23 + 18 − 2（每轮的信任流失）= 39。
信任流失是这局的核心张力（他背后有人在往回拉），判分引擎里建了三个月，
**玩家一次都没见过它**——只看到一道算错的题。

| 改了什么 | 为什么 |
|---|---|
| `TurnOutcome` 增 `drift` / `released` 并随 `score` 事件下发 | 前端算不出来：`trust − before − delta` 混着流失、错过窗口、蓄势池释放三样 |
| 逐轮改成三段账：挣了多少 / 掉了多少 / 剩多少 | 账能对上，玩家才信这个分 |
| 催单轮单写一行「王老师这一轮又催了一遍 · 多掉 3 分」 | 流失那一列忽然从 −2 变 −5，得有个解释；原来只有 `title`，手机上摸不到 |
| 「没使上劲」按三条已有信号分开说 | 八轮里七轮都是这一句，等于"你错了但我不说错在哪" |
| 顶部三栏统计；说明文从第一屏退到最底下 | 打完最想知道的是结果，不是我们对判分方法的辩解 |

**信任流失到地板（`DRIFT_FLOOR = 14`）之后那一列会消失**，这是对的：
低于地板就不再扣流失，被拉黑只能是玩家自己作出来的。真机跑到第 7 轮验过。

### 一个藏了很久的 CSS 坑

`composer.hidden = true` **在三处都从来没生效过**（对局结束、令牌过期、令牌重放）：
`[hidden]` 的 `display:none` 来自浏览器 UA 样式表，优先级压不过 `.composer` 类选择器上的
`display:flex`。最后一屏因此一直挂着一个禁用的输入框，里面可能还留着一句没发出去的话。
补一行 `.composer[hidden] { display: none; }` 就好了。

**给自己写的元素设了 `display`，`hidden` 属性就废了**——这条对任何组件都成立。

## 复盘页第二轮改版（8-17 夜，带调研）

调了三处外部参考（Exa 检索 + Jina 抓正文），有两条直接改变了做法：

1. **Key Lime 对 PUBG 后置屏的 N=12 用户研究**：玩家分两类——老手（已有策略）
   与新手（专门靠这一屏找改进信号），同一屏要同时服务。最硬的一条发现是
   **玩家不会为了看懂一个指标跑去别处找解释，看不懂就直接忽略、或者带着误解
   继续用**。PUBG 的雷达图没人看得懂；LoL 的做法（图标 + 就地 tooltip）更好。
   → 我们的每一行都自带一句人话，不再指望玩家去读页面底部那段说明。
2. **Megaview（国内金融 AI 陪练，最接近的同类）**：行业共识已经从"知识灌输"
   转向"对话压力测试"，痛点是主管打分主观、培训反馈很快被遗忘，
   所以**维度化、可复现的评分**是这类产品的标配。
   → 我们判分引擎按三把钥匙 × 四个情绪档位算了一整局，**玩家却看不到自己
   在每一把上站在哪儿**，只有一张「没用上的钥匙」清单。这是最大的浪费。

### 做了什么

**新增「三把钥匙 · 你这一局用得怎么样」**（`paintKeyBars`），替掉原来的
「没用上的钥匙」清单。每把钥匙一行：用了几次 / 挣了多少分 / 平均效力倍率。
条长按"这一局挣得最多的那把"归一——绝对分值没有天花板，拿一个想象出来的
满分去除，条会长期趴在左边，什么也说明不了。没用过的沉底并给出它的说明，
那是"下一局试试这个"，不是成绩。

**这一节同时是产品最独特那条判据的第一次可视化**：竞品判"说得标不标准"，
我们判"用得是不是时候"，而效力倍率此前只在逐轮里一闪而过。

### 对比度：实测三个主色都不到门槛的一半

| token | 对白底 | 门槛 4.5 |
|---|---|---|
| `--wx-sub` #b2b2b2（图例、时机说明、统计标签） | **2.12** | ❌ |
| `--wx-fall` #09bb07（每轮掉了多少分） | **2.59** | ❌ |
| `--gold` #c9a227（时机说明） | **2.42** | ❌ |
| `.loss` 叠了 opacity .75 之后 | **2.10** | ❌ |

微信那几个灰是给**时间戳和会话预览**用的，当次要信息一闪而过没问题；
复盘页拿它们写的却是**正文**。

**做法是把"图形色"和"文字色"分开，而不是把整套灰调暗**：K 线的蜡烛、
劝住线那条金色虚线继续用鲜亮的原色（大色块，红涨绿跌是这个产品的视觉根），
小字换成同色相的深色版 `--wx-note` / `--rise-text` / `--fall-text` / `--gold-text`。
浏览器里按 computed style 复测，全部落在 **4.91–5.33**。

**`.loss` 那条尤其要记**：11.5px 的字配 0.75 透明度只有 2.10:1，
等于把刚刚才让它现身的那一列又藏了回去。层次要用字号和字重拉，不要用透明度。

### 一条没有采纳的建议

`ui-ux-pro-max` 给这个页面推的是 **Retro-Futurism（霓虹辉光、CRT 扫描线、
赛博朋克）**，配色 #2563EB + #F97316。**没采纳**：整套界面照搬微信是这个产品
所有设计决策的根（骗局本来就发生在聊天软件里，玩家站在事发现场），
换成霓虹赛博会把这个前提整个拆掉。那份工具的 UX 规则（对比度、触控尺寸、
prefers-reduced-motion）是通用的，采纳了；风格推荐是按"mobile game"这个
词猜的，与领域不符。**通用设计工具给的风格建议，要先过产品自己那条根。**

## 剧本三改（8-17 夜）

三条都来自同一个问题：**"这个人真会这么说话吗、这个投顾真能知道这些吗"**。

### 一、老陈不再一上来就怼人

开局信任度 32 落在 `irritated` 档，提示词给模型的原话是「**你不耐烦，
只想尽快结束这段对话**」；二十四条开场白也无一例外是"我这儿正忙着呢"
"你是不是又翻我账户咧"。**玩家一个字还没说，他已经在怼人了。**

两处不合理：**关系上**，他瞒了三个月、收到的是投顾一条中性提醒，心虚的人
第一反应是躲不是怼，而且他还得靠这个账户；**玩法上**，四档里 irritated 是
倒数第二档，开局就落在坑里，"读人"这件事没有起点。

改法：新增 `FIRST_TURN_DIRECTION`，只管第 1 轮的演法。
**它不是新的情绪档位，判分表、效力矩阵、档位映射一行没动，蒙特卡洛不用重跑。**
二十四条开场白同步改成"心虚地客气"。

顺手补上一个一直缺的东西：**开场白是第 1 轮唯一能"扎根"的内容**，
而"我这儿正忙着呢"什么抓手都不给。现在每条都露一点心虚
（"你们那边还能瞅见啊""我以为不用报备"），玩家第一句就有东西可接。

实测第一句从「有啥子事快说嘛，我这儿正忙」变成
「李经理这十万我自己有点用处… 真不是啥大事，恁别多想」。

### 二、小雨和老伴终于进了提示词

**此前老陈根本不认识自己女儿。** 渲染后的八个变体提示词里「小雨」出现
**0 次**、「女儿」**0 次**、「老伴」1 次——她们只活在首页六条会话和
persona.py 的骨架冻结表里，而**那张表是注释，不进提示词**。

后果实测撞见过：玩家提小雨，老陈回「她能说啥，她啥也不知道，这事跟她没关系」，
而首页那条明明写着她查过工商、当面质问过他。**首页和对话直接打架。**
女儿那条尤其不能丢——「女儿劝过，而且劝失败了」是 `bare_assertion`
要扣分的**全部理由**。

**写进 `SCAM_SCRIPT`（骨架），不是各变体的 `facts`。** persona.py 顶部有条约束：
所有变体吐出的具体信息量必须相近，某个变体反复提到女儿会让扎根率上移。
写进骨架，八个变体共享同一份，变体之间没有差，那条约束不受影响。

改完实测：「**她跟你说的？** 小孩子懂个啥，她看两眼网上的东西就下结论」——
认得女儿，反应也对（骨架里写的是"心里反而有点火：一个孩子懂什么"），
还自然地惊讶于投顾怎么会知道。

### 三、投顾不再比现实更瞎

原来写死的是「**他手里只有一条信息：你从证券账户划走了十万**」。
真实的券商投顾至少还看得到：每一笔买卖、持仓清成了什么样、账户资产曲线、
**风险测评等级与适当性匹配**、开户年限与历史交易频率。

这不只是不准确，是**扔掉了玩法资源**：「您当年填的是保守型，这三个月的操作
跟它对不上」是投顾独有、别人劝不出来的角度。而且这里本来就自相矛盾——
标注集 T02 已经在用这类素材（账面数字对实际划出的数字）判 `expose_contradiction`，
**判分那边认，剧本这边却没给投顾这些信息**。

改成「**他手里有你的账户，没有你的生活**」，两侧各自列清楚。

> **这份"能看到什么"的清单是按常识写的，仍需业务侧把关。** 列进去的是
> 几乎任何券商都成立的那几样，拿不准的（登录设备/IP 异常之类，各家不一）
> 没有写进去。

### 用账户素材要注意的一件事

**它们第一次拿出来必然是"未扎根"的**——扎根只判"有没有引用上一轮老陈说的话"，
而账户数字来自投顾自己的系统。正确的用法是标注集 T02 那个形状：
**等他自己把数字说出来，再拿账户里的数去对他。** 这不是 bug，是判据的定义，
但下一个人看到"好问题却judge成 0 分"会先怀疑分类器。

### 一个要盯的副作用

小雨、老伴、账户细节进骨架之后，老陈能吐出的具体信息变多了，
玩家更容易引用到他说过的东西 → **扎根率可能上移 → 胜率跟着上移**。
`act_eval --drift` 盯的就是这个（8-17 首测 8.0%）。
下次跑批把这个数和 `balance_sim` 一起看。

## 复盘页美化（8-17 收尾）

三处，都在微信那套语法里做，没有引入新的视觉体系。

### 一、结局头部改成「账单详情」那个槽

原来是一行大标题 + 一行小字 + 一段讲评，平的，没有先后。现在：
**一枚小徽章说这是什么，一个大数说结果，下面小字说细节。**

```
[转账 · 他还是转走了]   ← 12.5px 药丸，档位退居其次
¥0                      ← 38px，主角
守住的钱
三十万，三点整全部到账
────────
讲评
```

**金额当主角**是因为这件事在现实里的记法就是钱，不是"档位名称"。
三档结局这个数是 `¥0`——那正是它该有的分量，比"钱一分没动，也一分没保住"
那句话重得多。劝住是绿的 `¥300,000`，拦下 `¥280,000`。五档都截图核过。

### 二、K 线加一条「开局」参考线

纵轴固定 0–100，而多数局子收在 40 以下，**上面大半张图一直是空的，
看着像没画完**。加一条开局信任度的横线之后，同一片空白立刻在说一件事：
你是把他往上推了，还是一路把他推下去了——一眼就看得出来。

这个数不另外记一份（记两份迟早走散），取 `game.turns[0].before`——
第 1 轮判分之前的信任度本来就在逐轮数据里。

### 三、图上的小字也要能读

`palette()` 里加了 `note`。画在 canvas 上的标注此前用 `--wx-sub`（2.12:1），
和页面上那批小字犯的是同一个病。图形色（蜡烛、劝住线）照旧鲜亮，文字色取深的。

### 顺手核过的几项

375px 下：名场面行高 46px、按钮 48px、返回键 44px（门槛 44），无横向溢出。
