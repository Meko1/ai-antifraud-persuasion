> 一句话找东西：要填表 → 第二节；要出图出视频 → 第六节；
> 要部署 → 第七节；被评委问住 → 第八节。

## 关键状态

| 项 | 值 |
|---|---|
| 报名 | 已报名，可重复提交 |
| 参赛形式 | 单人参赛（规则允许 1–3 人，选了 1 人） |
| 作品类型 | 金融财经 |
| 线上状态 | 图集 / 演示视频 / 作品展示 三个页签均已就位 |

和业务逻辑推的，没有条线背书"，别含糊。

## 一、大赛硬约束（规则出处）

### 报名与提交

- 团队 = 1 名队长 + 0~2 名队员，以战队为单位提交与展示
- 作品须原创、不侵犯第三方知识产权；演示链接需可在浏览器正常访问
- 前台默认展示马甲昵称与参赛信息，真实姓名可选；部门信息固定展示
- 提交后进入初审，留意个人中心作品状态与系统通知；赛程节点以平台公告为准
- 内部数据须脱敏，不得上传敏感凭证、密钥
- 桌面端作品需提供可嵌入网页的 Web 展示方案（`FRAME_ANCESTORS`，见第七节）
- 禁止刷票、恶意拉票；平台记录投票与互动行为，异常数据复核

### 展示页结构（投票用户真正会看到的界面）

- 左上：作品标题 + 标签组 + 团队名 + 成员名 + 职能标签 + 一句参赛宣言
- 中部：**三个页签**——图集 / 演示视频 / 作品展示；覆盖层是**弹幕**
  （评论以弹幕形式飘过截图之上，图集上半部要留跑道）
- 右侧：当前票数 + 「为作品投票」按钮
- 右下：评论区（最新 / 最热），带「精选评论」与楼中楼回复

### 部署

| 条目 | 约束 |
|---|---|
| 端口 | 固定 21818 |
| 生命周期脚本 | `start.sh`/`stop.sh` 必在 ZIP 根目录，`install.sh` 可选，不许混模式 |
| ZIP 校验 | ≤500 MiB / ≤10000 条目 / 解压 ≤2 GiB / 无 `..`、无盘符、无反斜杠 |
| 自检 | ZIP 中不含密钥、密码、令牌 |
| 服务器网络 | 独立网段，与其他内部网段隔离，可访问公网 |
| 安全扫描 | 部署后平台联合安全部门做漏洞扫描，严重问题限期整改 |

## 二、报名表定稿（可以直接抄）

字数均含标点。

### 作品名称（15/20 字）

> **两万局模拟，新手几乎一局没劝住**

"模拟"两个字一个都不能省——那五个 0.0% 是 `balance_sim` 里 `novice` 这个
**模拟人设**跑出来的，不是真人成绩。"几乎"不能删：六个场景合计 12 万局里
zhou、liu 各有 1 局劝住，不是真零。**任何精确局数不进对外文案**，只进
下面这份文档。

不加「妙想」前缀：这个名字要的是让人**想点**而不是让人**看懂**，前面挂
品牌会把第一眼引到品牌上，盖过"0.0%"。品牌对齐放在团队名称与创意思路末句
（「设计为妙想的账户安全技能」是接入形态的陈述），不放在作品名称位——
那里读起来就是"这是妙想的官方产品"，产品归属不该由参赛作品替品牌方下结论。

**填表时把 `<品牌名>` 换成真名再交，本仓不落那个词。** 全仓的公司与品牌
名称一律用 `承办方` / `自研金融大模型` 指代，与 [TECH-DESIGN](TECH-DESIGN.md)
的 `<对照模型>` 同一套约定。产品名仍是「AI 反诈劝阻」（`app/main.py`、
`static/index.html`、分享卡水印三处），不随参赛作品名改。

### 作品类型

> **金融财经**

### 作品标签（5/5）

## 三、为什么是这个定位

### 1. 分级结构——现有 demo 是最高一级，外面包两层叙事骨架

| 层级 | 触发条件 | 干预形态 | 现有代码对应 |
|---|---|---|---|
| Tier 0 | 低风险异动 | 静默记录 + 一句话提醒，不打断 | 无，需新写 |
| Tier 1 | 中风险异动 | 60–90 秒快速核验 | 无，需新写，量级不大 |
| Tier 2 | 高风险异动（杀猪盘/冒充公检法/荐股群等已建模的六个场景） | 现有十轮角色互换对话 | 已完成，[`app/scoring.py`](../app/scoring.py) 判分引擎、[`app/scenario.py`](../app/scenario.py) 六个场景、[`app/persona.py`](../app/persona.py) 28 个人格，两万局蒙特卡洛标定过 |
| 处置闭环 | 任意层级结束后 | 核验收款方 / 转人工 / 安全返回交易 | 无，需新写 |

这张表是目标形态，不是落地顺序：[POSITIONING「路线」](POSITIONING.md)在
这三层之前加了一步——**自愿进入的账户安全入口**（不接异动流水、不动交易
主链路）。**材料里可以讲分级，但被问到"第一步做什么"时，答案是自愿入口，
不是 Tier 0。**

**为什么不直接拿现有三分钟对局去投**：官方"作品方向建议"写的是"将 AI 能力
融入真实业务或日常工作场景"，奖励的是"这东西怎么接进真实业务流程"，不只是
"这个 demo 好不好玩"。而现有产品最大的空缺是：判分只判"信任度"，从不判
"有没有真的做安全动作"——对话结束之后用户该干什么，产品里一直没有答案。
加处置闭环，是把这个空缺显式补进定位里。

**为什么不是完全推翻现有 demo，改成一个纯后台风控层**：现有三分钟角色
互换对话是这个项目在一堆"泛财经类应用"里唯一有传播力和辨识度的资产，花了
两个月蒙特卡洛标定。参赛材料应该让它继续当 demo 主角，新增的两层是包在它
外面的叙事骨架，不是替代品。

### 2. 法规锚点

《反电信网络诈骗法》确实有两块内容与本作品形态相关，但**义务人不是券商**：

- **第十八条**：异常账户与可疑交易监测；识别后可"核实交易情况、重新核验
  身份、延迟支付结算、限制或者中止有关业务"。义务人：银行业金融机构、
  非银行支付机构
- **第三十四条**：公安机关会同金融、电信、网信部门**组织**上述机构与电信
  业务经营者、互联网服务提供者**等**建立预警劝阻系统

**这两个条号已逐条核对，可以写。其余条号不要写。** 第四十条的罚则同样只罚
银行业金融机构与非银行支付机构。

**材料里怎么写**：只写"呼应""对齐"，**绝不写"依据……本公司必须"**。
如果评委问"券商有这个义务吗"，正确答案是：**没有，这是主动做的**——
而主动做的理由不在法条里，在下一节。

### 2.1 真正的推力：投诉与声誉

某券商 2025 年接到假冒案件线索超 1900 条（同比 +280%），涉案 3000 万元，
总部来访受害投资者 150 人次；去年以来被仿冒的券商 30 余家，头部机构均在列
（证券时报／中证协，[EVIDENCE §六](EVIDENCE.md)）。

**这个理由不需要任何法律解释就成立**，而且它是评委席上真实存在的痛。

同一篇报道里还有一条**对本作品的机制直接有利**的事实，材料里值得单独讲：
骗局会要求受害者签保密协议，**明确禁止向证券公司、监管部门、公安机关透露
任何信息**。第十八条给银行备的那套动作——核实交易情况、重新核验身份——
**两个都是问答，而对面那个人已经被预先训练成会撒谎**。角色对调不要求
披露、不要求承认，是这套预设防御目前唯一绕得开的形态。

### 3. 品牌对齐——为什么敢往自研金融大模型上靠

承办方的自研金融大模型已通过网信办备案、已向全市场用户开放，官方口径明确
要"融入公司各产品各业务条线""开放共生"——目前落在资讯、行情、自选、客服
等场景，**账户安全不在其中，这是空白**。**这是内部员工创新赛，不是对外
公开赛**：员工在公司内部对齐公司自己的旗舰 AI 平台，是主动表明生态归属，
不是蹭外部商标。

分寸留在哪：材料里写"设计为可对接该生态的数据与 Agent 能力"（表达兼容性、
技术可插拔），不写"这是它的官方新产品"——后者是产品/品牌部门的决定权限，
参赛作品不该替他们下结论。

## 五、材料里必须如实框住的三个风险

1. **核心成功指标（24 小时内转出放弃率）赛期内测不了**，需要接入真实交易
   系统回传，这个仓库没有也不该有。材料里不要暗示"已验证有效"，框成
   "设计了对照组口径、指标定义清楚，下一步是接入真实异动流水"。
2. **处置闭环的三个动作现在是设计，不是功能**——见第四节，材料措辞要对得上。
3. **法规适用性已查清，结论为否**——见第三节 2。材料里不许出现任何暗示券商
   有法定劝阻义务的表述；被问到就直接答"没有义务，是主动做的"，然后讲
   2.1 那组投诉数字。
4. **"角色对调"这个机制有外部实证，但不能讲过头**："角色对调"现在有外部
   实证了：CHI 2026 的 ROLESafe（n=144，中国老年人，四组对照）里"去劝一个
   受害者"这一组识别 F1 0.85，是三种角色里最高的，显著优于对照组
   （[EVIDENCE §五](EVIDENCE.md)）。**但那篇的结局变量是"诈骗线索识别能力"，
   不是"取消了一笔正在进行的转账"**，且自我效能感四组无显著差异。材料里
   能写的只有一句：**"机制有同行评议的实证支持"**——不能写"已被证明能拦下
   转账"。

| 没有配退路（ADR-0007） | token 用尽那天接不住 | 填 `PUBLIC_LLM_BASE_URL/API_KEY/MODEL`，重启 |
| 退路本身探不通 | 现在没事，用尽那天会连着失败两次 | 核对 `PUBLIC_LLM_*` 三个变量与账号余额 |

- [ ] 手动确认一次：`curl -s 'http://127.0.0.1:21818/healthz?probe=1'`
      → `llm_probe.ok` 与 `llm_probe_fallback.ok` **都要是 true**
- [ ] **`REDIS_URL` 也要放进 `~/.ai-antifraud-persuasion/env`，本地 `.env` 不会
      跟着 ZIP 走。** 不填不影响对局（旁路设计），但排行榜/百分位全场都停在
      占位文案「排行样本积累中」。凭证见组委会通知，格式
      `redis://:口令@10.126.192.12:7001/0`（库号必须是 0，`app/stats.py`
      的 `force_db0` 会强改并打 WARNING，直接写对省一次警告）。
      填完 `./stop.sh && ./start.sh` 重启后确认：
      `curl -s http://127.0.0.1:21818/api/stats?sid=chen` → `"available": true`
      （本机因网段隔离连不上这个内网地址，**只能在服务器上验**）
- [ ] `env` 里 `LLM_PROVIDER` 必须是 **`internal`**。写成 `public` 会同时塌掉
      两件事：主模型不是 claude-opus-5，**而且 ADR-0007 的自动降级整条不存在**
      （`_load_fallback()` 只在 `internal` 时加载 `PUBLIC_LLM_*`）

### 怎么判断现在到底在用哪个模型、有没有在发罐头

**三个问题，三处答案，都在 `/healthz` 上**：

```bash
curl -s http://127.0.0.1:21818/healthz | python3 -m json.tool
```

| 问 | 看哪一位 | 怎么读 |
|---|---|---|
| **配的是哪个模型** | `llm_model` | 启动时定死，比如 `claude-opus-5` |
| **现在真正在答的是哪个** | `llm_failover.active_model` | 和上面**不一致**就说明已经自动切到退路了；`switched_at` / `reason` 说明什么时候、为什么 |
| **是模型在答，还是在发罐头** | `line_sources` | `{model, fallback, absorbed}` 逐轮累计 |

`line_sources` 是这三位里唯一反映**运行中**而不是**启动时**状态的：
探测通过之后网关照样可能每一轮都超时，那时候 `llm_probe.ok` 仍是 true，
而玩家拿到的每一句都是兜底台词。

- `model` 在涨 = 正常，台词是大模型写的
- **`fallback` 在涨 = 在发罐头**。网关通但每轮超时，或者已经切到退路而
  退路也在超时
- `absorbed` = 注入吸收，玩家在试图操纵系统。它是功能，不是故障

单轮也能看：`/api/game/turn` 的 `score` 事件带 `line_source`。
**别拿 `degraded` 当这件事看**——那一位说的是*分类*没判成，
和台词是谁写的是两回事。

- [ ] 平台若用 iframe 嵌展示页：`env` 里填 `FRAME_ANCESTORS=<平台域名>`，
      否则「作品展示」页签是一块空白（默认仍是 `'none'`）
- [ ] **把展示页 URL 填进 `static/index.html` 的 `<meta name="af-share-url">`**
      （二维码指向展示页，那是唯一同时能"看懂"和"投票"的页面）。
      **静态文件实时读盘，改完刷新即可，不用重启**
- [ ] 填完扫一次那个码，确认真的落在展示页上

## 八、被问到时的三条硬边界

**这三条不许含糊，含糊比说"没有"更掉分。**

| 问 | 答 |
|---|---|
| 券商有法定劝阻义务吗 | **没有。** 《反电信网络诈骗法》全文未点名证券公司，罚则也不含（[EVIDENCE §一](EVIDENCE.md)）。这是主动做的，推力是投诉与声誉：某券商 2025 年假冒案件线索超 1900 条、同比 +280%、总部来访受害者 150 人次 |
| 效果验证过吗 | **没有。** 24h 内转出放弃率一次都没量过——它需要接进真实异动流水。现在有的是**口径与对照组设计**，不是结果 |
| 角色对调有依据吗 | **机制有同行评议的实证支持**（CHI 2026 ROLESafe，n=144，"去劝受害者"组识别 F1 0.85 最高）。但那篇的结局变量是**诈骗线索识别能力**，不是"取消了一笔正在进行的转账"——**不能说"已被证明能拦下转账"** |

同理，材料里**不出现**：已验证有效 / 降低 X% / 依据某法本公司必须 / 这是
某平台的官方产品。

## 九、赛期打法

外部结论支撑下面每一条打法：

- **质量决定资格，不决定排名**——Salganik/Dodds/Watts 的音乐实验
  （*Science* 2006，14341 人）：加入社会影响后，成功的不平等与不可预测性
  同时上升，最好的很少垫底、最差的很少夺冠，**但除此之外任何结果都可能
  发生**。把排名交给"作品自己会说话"，等于交给随机数
- **位置比社会影响本身还重要，位置由早期票决定**——Hogg & Lerman（*Human
  Computation* 2015）：位置的影响约是社会影响的两倍。Muchnik/Aral/Taylor
  的随机实验（*Science* 2013，10 万+ 条内容）：平台管理员投下的第一票是
  正的，最终得分平均高 25%，且正向从众会累积。**早期票不是"先拿几票"，
  是"决定你后面能不能被看见"**
- **被转发的是高唤醒情绪，不是好结果**——Berger & Milkman（*JMR* 2012，
  近 7000 篇 NYT 文章）：预测转发的是唤醒度而不是正负，敬畏/愤怒/焦虑会
  被转发，悲伤与满足不会

漏斗：`展示页曝光 → 图集第一张 → 点进作品/看视频 → 玩一局(3min) → 回展示页
→ 按下投票`（另一条支线：转发分享卡 → 新观众）。最大的漏点是**玩完之后
已经离开展示页，投票按钮不在眼前**；展示页弹幕飘在截图上半部，图集标题
要躲开。

| 打法 | 内容 | 状态 |
|---|---|---|
| S1 · 分享卡换主角 | 从「你输了多少」换成「差 2 倍」——低唤醒的沮丧不被转发，时机对照的倍数是高唤醒、且是全作品唯一竞品没有的判据。结局徽章仍在卡头、金额退到统计行，**换的是主角，不是事实** | ✅ 已做（[`static/history.js`](../static/history.js) 的 `cardHero()`，取数在 [`static/contrast.js`](../static/contrast.js)，复盘正文与分享卡共用同一份取数） |
| S2 · 二维码指向展示页，不是作品本身 | 展示页是漏斗上唯一同时能"看懂"和"投票"的页面。改 `static/index.html` 那行 `<meta name="af-share-url">` 即可，静态文件实时读盘，不用重启 | ⏳ 等作品过审拿到展示页 URL |
| S3 · 复盘末尾一个"回去"的出口 | 复盘最后一行一个链接，不是弹窗、不是遮罩；文案走"给个反馈"而不是"投一票"。由同一个 meta 决定显不显示，没配就没有这一行——本地跑的人不该看见任何参赛痕迹 | 代码已就绪 |
| S4 · 图集关键信息躲开弹幕带 | 展示页弹幕飘在截图之上，标题下移或压深底色带 | ✅ 已做（[`tools/capture_materials.mjs`](../tools/capture_materials.mjs) 的 `--danmu`） |
| S5 · 演示视频 60 秒，前 12 秒把角色对调演完 | 分镜：0–3s 按下「确认转出」／3–8s 被拦下那一面／8–12s「请你坐到对面」／12–45s 对局三个来回 + 一次判分／45–55s「同一句话，换个时候说，差 2 倍」／55–60s 作品名 + 二维码。字幕全程硬字幕——投票者多半静音在会议间隙看 | 见第六节 |
| S6 · 第一波票集中在一小时内 | 作品过审后定一个时间点，把最先愿意支持的十几二十人约在同一小时看 + 投。真人、真看、真评论；也别压到十分钟——一小时窗口既真实也不会长出机器特征 | 分发时执行 |
| S7 · 评论质量 > 票数 | 一条两句以上的具体评论（"我第 7 轮才想起来问用途"）价值远高于一票。别发统一话术，一眼假，且赛制会复核异常互动数据。作者本人逐条认真回 | 分发时执行 |
| S8 · 请人"给反馈"，不请人"投票" | "帮我看看，玩一局三分钟"比"帮我投一票"既更安全也更有效。一句话 + 直达链接 + 截止日期。**最常见的失败不是作品不好，是没有清楚地开口** | 分发时执行 |
| S9 · 拉一位风控/合规条线的队友 | 同时结掉"单人参赛"与"归属论据没有从业者确认"两件事。部门信息固定展示，那位队友本身就是社会证明 | 只有所有者能做 |

### 红线（材料与行为都照这条走）

- 不刷票、不建互投群、不用新号、不发统一话术
- 平台记录投票与互动行为，异常数据复核
- 为拿票不动判分（[ADR-0001](adr/0001-scoring-authority-belongs-to-the-program.md)）、
  不越过主张边界（[README](../README.md)）——没量过的仍然说没量过
