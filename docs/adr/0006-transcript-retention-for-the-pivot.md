# 落对局语料：ADR-0003「服务端不存任何东西」的一处例外

服务端开始留存一份**对局语料**：每轮的玩家发言、模型台词、判定结果（命中、扎根、分值、判分档位）。落库前一律过脱敏（[`app/redact.py`](../../app/redact.py)），默认关闭，由 `TRANSCRIPT_RETENTION` 显式打开。

**这是一处例外，不是推翻。** [ADR-0003](0003-game-state-is-client-held-and-signed.md) 说对局状态由客户端持有并签名、服务端无状态——那一半原样保留：对局**状态**仍在签名令牌里，服务端仍不存会话，重新部署仍然不踢任何人下线。新增的只是一条**只写不读、任何一局对局都不依赖**的旁路。判断标准就一条：把这份语料整个删掉，对局能不能照常打完。能，所以它是例外而不是推翻。

## 为什么是现在

写 ADR-0003 的时候，产品是一个比赛期的单机训练器，"不存"是完全正确的取舍：部署简单、无状态、重启不丢局，而存下来的数据当时没有任何用途。

[转向 C 端异动干预](../PIVOT-C-END.md)之后有了用途，而且是唯一一个可能的护城河：**真实对话 → 专家标注 → 更准的分类器 + 更真的效力矩阵**。七把钥匙和五个场景，竞品照着抄一周就有；三年的标注语料抄不走。留存这件事从"没必要"变成"不做就没有后天"。

另一条同样具体：[POSITIONING](../POSITIONING.md)「成功标准」现在要求 24h 转出取消率**必须能和对照组比**。对照组是一个需要跨会话对齐的口径，而当前架构里跨会话的东西一个都没有。

> **2026-08-29 补注（不改本决策，只对齐词）**：上面那个指标现在叫**24h 转出放弃率**。银证转账是实时划转，执行后没有"取消"这个动作可撤，改名理由见 [EVIDENCE §二](../EVIDENCE.md)。**本决策的论证一个字都不受影响**——它依赖的是"对照组需要跨会话对齐"，与指标叫什么名字无关。下面「后果」一节里那句"24h 取消率与 30 天二次触发率的对照"同此。

**这条 ADR 存在的价值就在这里**：三个月后有人翻到 ADR-0003，会发现代码和它写的不一样。那时候他要能读到"为什么反转"，而不是猜是谁偷偷改的。

## 范围：存什么，以及**不**存什么

存（每轮一条，见 `transcripts.build_entry`）：

| 字段 | 为什么要 |
|---|---|
| `gid` / `sid` / `round` | 把一局的十二轮串成一段对话。语料的价值在整段对话上，逐轮拆散没法标 |
| `utterance` / `reply` | 脱敏后的玩家发言与模型台词。**这是全部价值所在** |
| `hits` / `grounded` / `delta` / `judged_mood` / `efficacy` | 模型当时判成了什么、规则表算出了什么。标注的人要拿它当对照 |
| `degraded` | 这一轮网关抖了、根本没判成。不标出来，它在语料里和"玩家说了句废话"长得一模一样 |

**不存，且明确划在范围外**：

- 账号、持仓、资产、交易流水 —— 任何来自异动信号那一侧的数据
- 用户标识、手机号、设备指纹、IP
- 触发这段对话的那条真实异动的内容

最后一条要专门说：转向之后这段对话由一条**真实的资产异动**触发，把那条异动一起存下来是最自然不过的下一步，也正是这里划死的那条线。语料要的是"人怎么劝人"，不是"谁在什么时候转了多少钱"。`gid` 是每局随机生成的对局号，不是用户标识——同一个人玩两局是两个 gid，跨局关联不起来。

## 两条硬要求

**一、脱敏，而且脱敏规则要有测试。** 见 [`app/redact.py`](../../app/redact.py) 与 `tests/test_redact.py`。做法与 `app/safety.py` 相反：safety 是整句替换（输出给玩家，不能留空档），这里是**只挖掉那一段、句子留着**——整句替换会把样本本身毁掉，而留存的唯一理由就是这些样本。

脱敏脱不掉的东西写在明处：中文姓名没有可靠的形状，夹在句子中间的抓不到；住址、单位、病史这类自由文本同理。**所以脱敏不是唯一的防线，上面那份"不存"清单才是**——一层挡不住的，靠根本没往那儿存挡。

**二、在用户开口之前明确告知留存与用途。** 那句话由服务端随 `/api/game/start` 下发（`transcripts.disclosure()`），渲染在聊天窗口第一条消息的上方，不藏在任何链接后面。它是一个函数不是一段静态文案：留存开着和关着说的不是同一句话，写两份必然有一天只改一份，而改错的那一份是在对用户说谎。

## Consequences

- **默认关闭**。不显式打开就一条不存，行为与 ADR-0003 时代完全一致。留存不该由"忘了配环境变量"来决定方向。
- 存在 Redis 上，条数封顶 20000、留存 90 天（TTL 每次写入顶回去，量的是"最后一次有人在玩"）。共享实例上不能无限长，那是别人的机器。
- 写入纪律与 `app/stats.py` 一致：不 await 在对局路径上、异常全吞、惰性建连。**Redis 挂了只是不留存，游戏照常。**
- 只写不读：服务端没有任何读取这份语料的接口。导出与标注是离线的事，线上不开这个口子。
- 90 天上限意味着**长周期的对照组分析在这套存储上做不了**。真要做 24h 取消率与 30 天二次触发率的对照，需要的是业务侧的数仓，不是这个 Redis 列表——本决策不假装解决那件事。
