# 不自动切换模型 provider

内网模型网关与公网模型接口保留双 provider 抽象，但 provider 在**启动时**由环境变量选定，运行期不做自动故障转移。网关故障时只降级到兜底台词，不改变数据流向。切换 provider 是人工决策：改环境变量并重启，两分钟内完成。

自动转移会让用户输入在无人知情的情况下开始流向公网模型。玩家能在输入框里打任何东西，而这是券商内部环境——同一把合规尺子已经否决过「让玩家扮演骗子」的玩法，静默外流不应低于那条线。何况兜底台词库已经能接住网关故障，自动切换换来的边际可用性很小，换走的合规确定性很大。

## Consequences

- 后台需持续探测网关健康度并在健康检查接口暴露，使投票期能实时观察、及时人工介入。
- 内网网关长时间故障时体验会降级到兜底台词，这是明确接受的代价。
- 保留双 provider 抽象仍有价值：目标服务器位于独立网段，拿到机器当天可能发现内网网关根本不可达，届时启动前切换即可。
