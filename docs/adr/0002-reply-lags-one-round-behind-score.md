# 台词落后分数一轮

每轮向模型并发两个请求：演绎请求流式生成劝阻对象的台词，分类请求判定玩家发言命中了哪些钥匙。演绎请求携带的是**上一轮结束时**的情绪档位，因此本轮台词并不反映本轮刚刚算出的信任度变化。

这不是缺陷，是刻意设计，有两个理由。工程上，分类的耗时被台词的流式输出时间完全掩盖，首字延迟等同于单次调用；若改为串行「先判后演」，首字延迟变成两次调用之和，在 2C4G 上会突破 3 秒首屏预算。戏剧上，人不会在一句话之内改变立场——玩家说中要害、对方嘴上仍硬、下一轮才松动，这正是真实劝阻的样子；「你一说他立刻服软」恰恰是谄媚感的来源。

## Consequences

- **不要"修复"它。** 未来读代码的人看到「台词用的是上一轮档位」几乎必然认为是 bug，改成同轮一致会让游戏立刻退回谄媚观感。
- 结局台词必须是终局判定后的**独立一次生成**，否则最后一轮的因果链会断（第 12 轮说中要害，台词却还在嘴硬）。
- 两类请求的降级属性不同，可以分别设定超时与优先级：演绎可降级到兜底台词，分类不可降级。
- 依赖 [0001](0001-scoring-authority-belongs-to-the-program.md)：只有当模型看不到分数时，两个请求才可以安全地并发。
