# 内网网关 token 用尽时，自动切到一个具名的、已购买的公网模型

修订 [ADR-0005](0005-no-automatic-provider-failover.md)。那条决策仍然成立的部分
**没有变**：切协议、切成"随便一个公网模型"，仍然是人工决策，仍然不做运行期猜测。
这条 ADR 只推翻其中一种、一个方向的自动切换——公司内网 AI 平台的 token/额度用尽时，
自动切到运维**已经显式配置好、自己付费购买**的 DeepSeek-v4-pro（`PUBLIC_LLM_*`）。

ADR-0005 否掉自动切换的理由是"用户输入在无人知情的情况下开始流向公网模型"。
这条理由在**这一种**场景下不成立：目的地不是"任意一个公网模型"，是运维自己开的账号；
判据不是"网络抖了一下就猜是不是该切"，是网关本身报出的一句具体错误——**这个仓库
自己在 2026-08-15、08-22、08-23 三次撞见过同一句**：`401 该令牌状态不可用`，每次
持续 8 小时以上，累计约 3400 次调用后出现。这与另一种 401（`ip restriction!`，
几分钟内自己恢复）是两回事，不能用同一个状态码去判。

内网网关 token 用尽这件事，历史发生率不低（三次），而且每次持续整整一个工作日——
兜底台词库接得住"网关抖一下"，接不住"接下来八小时每一句都是台词"。

## 决定

- `app/config.py` 在 provider 为 `internal` 时，额外无条件加载一份 `PUBLIC_LLM_*`
  作为 `Settings.llm_fallback`。**留空就是没有 fallback**，行为与改动前完全一致——
  这条路径只在运维自己填了公网凭证时才存在。
- `app/llm.py` 的 `LLMError` 新增 `quota_exhausted` 标记，判据是异常文本里是否含
  `该令牌状态不可用`。**不是任意 401**：`ip restriction!` 不触发切换，
  该等就等，那是 ADR-0005 那条自愈机制的原始意图，没有理由动它。
- `FailoverLLMClient` 包一层 `llm_client`：主 provider 报 `quota_exhausted` 时，
  **当次请求立刻重试到公网**，且这个进程**往后所有请求都走公网**——不会
  每轮都去试一个已知报废 8 小时的网关，那只会让每个用户多等一次超时。
  要切回内网，重启服务（ADR-0005 那条"改环境变量、两分钟内完成"的人工流程
  仍然管用，只是触发**第一次**切换不再需要人在场）。
- **切换必须可见**：ADR-0005 反对的核心是"无人知情"，这条 ADR 把它堵在
  `/healthz` 上——`llm_failover` 字段实时报告是否已切换、何时切的、原因是什么。
  自动，但不是悄悄的。

## 明确不做的

- 不会因为一次超时、一次网络错误就切换——那是 L1/L2 降级（`app/engine.py`）
  该管的事，兜底台词库继续接这一类。
- 不会自动切回内网。判定"内网好了"比判定"内网坏了"难得多（要不要探测、
  多久探测一次、探测本身要不要算进配额），而误判的代价是体验来回抖动。
  这次只解决"扛住整个工作日的中断"，不做自动恢复。
- 不会把这条自动切换的能力推广到"协议"或"provider 之外的任何维度"。
  仍然只有这一种信号、这一个方向。

## Consequences

- **合规姿态变了**：内网网关中断超过某个时长后，用户输入会开始流向一个
  运维自己选定、自己付费的外部服务（DeepSeek）。这是运维明确接受的代价，
  不是意外——账号本身就是为这个目的买的。
- `/healthz` 多一个字段，运维在切换发生的那一刻就能看见，不用等玩家反馈。
- 判分与安全层完全不受影响：`FailoverLLMClient` 对上层是同一个 `chat`/`stream`
  接口，`app/gateway.py` 一行都不用改。
- 新增的失败面：如果 `PUBLIC_LLM_*` 本身配错或欠费，切换会"成功"但公网调用
  接着失败，最终仍然落到 L1/L2 兜底——不会比现状更差，只是多绕一层。
