### 1.2 提交阶段（截图 3/4 · 报名前请阅读）

**作品提交须知**

- 队伍 = 1 名队长 + 0~2 名队员，**以战队为单位**提交与展示
- 作品须原创、不侵犯第三方知识产权；**演示链接需可在浏览器正常访问**
- 前台默认展示**马甲昵称**与参赛信息，真实姓名可选；**部门信息固定展示**
- 提交后进入**初审**，留意个人中心作品状态与系统通知
- 赛程节点、通道截止以平台公告为准

**作品规范**

| 条目 | 约束 | 本项目现状 |
|---|---|---|
| 标题 / 宣言 / 思路 | 20 / **50** / 200 字 | ❌ **「参赛宣言 50 字」这个字段本仓库从来没写过**，CONTEST-POSITIONING §一 只备了三件套 |
| 在线链接 + 图片 | 必须有可访问链接，**至少 1 张图**；视频可选 | ⚠️ 图一张都没准备 |
| 封面图 | **建议 16:10**，清晰、能代表核心场景 | ❌ 没有 16:10 素材。分享卡是 640×~700（≈1:1，[`static/history.js:166`](../static/history.js#L166)），**不能直接当封面** |
| 桌面端作品 | 需提供**可嵌入网页**的 Web 展示方案 | ❌ **见下面 P0-1，当前的响应头明确禁止被嵌入** |
| 内部数据 | 须脱敏，**不得上传敏感凭证、密钥** | ❌ **见下面 P0-2，`PACKAGE_INCLUDE_SECRETS=1` 正好在干这件事** |

**作品提交细则**

- 参赛组别按作品类型选：金融财经 / 开发辅助 / 其他创新方向
- 所需资源（虚拟机 / 测试环境 / 接口）如实填写
- **禁止刷票、恶意拉票**；平台记录投票与互动行为，异常数据复核
- 审核驳回后可修改重新提交

### 1.3 展示与评选（截图 2 · 作品样例页）

这一屏是**投票用户真正会看到的界面**，本仓库此前所有文档都没有描述过它：

- 左上：作品标题 + 标签组 + 团队名 + 成员名 + 职能标签 + 一句参赛宣言
- 中部：**三个页签 —— 图集 / 演示视频 / 作品展示**
- 中部覆盖层：**弹幕**（评论以弹幕形式飘过截图之上）
- 右侧：**当前票数 + 「为作品投票」按钮**
- 右下：**评论区（最新 / 最热），带「精选评论」与楼中楼回复**

**这一屏对产品的三条硬含义：**

1. 「作品展示」页签几乎一定是把在线链接**嵌进 iframe**——这与
   「桌面端作品需提供可嵌入网页的 Web 展示方案」是同一句话的两种说法。
2. 用户是**先看图集、再决定要不要点进去玩**。第一张图承担全部转化。
3. **票数是这场比赛的可见计分板**，而
   [POSITIONING.md](POSITIONING.md#L159) 明确把「分享率」判成作废指标。
   这个冲突不是文档问题，是真实取舍，见 §二·视角 6。

## 二、六个视角的问题清单

编号规则：`P0` = 可能让作品直接不成立；`P1` = 明显掉分；`P2` = 打磨。
每条都带仓库内证据，没有证据的写成「待确认」而不是断言。

### 视角 1 · 资深专家（架构 / 工程 / 安全）

#### P0-1 响应头明确禁止被嵌入，而大赛展示页大概率就是 iframe

[`app/main.py:104`](../app/main.py#L104) 与 [`app/main.py:110`](../app/main.py#L110)：

```
Content-Security-Policy: ... frame-ancestors 'none'
X-Frame-Options: DENY
```

实测（`curl -D-`）两条头都在生效。含义是：**任何页面都无法把这个作品嵌进
iframe**。而作品规范白纸黑字要「可嵌入网页的 Web 展示方案」，样例页上又确实
有一个「作品展示」页签。

一旦平台用 iframe 呈现，投票用户在展示页上看到的是一块空白或
「拒绝连接」——**而作者自己点在线链接是好的，很可能到最后都不知道**。

修法很便宜且不降安全等级：加一个环境变量，把允许的父页面来源做成白名单，
**默认仍然是 `'none'`**，只在部署到大赛平台时显式填一个域名。

#### P0-2 打包开关会把真实密钥打进要上传的 ZIP

[`package.sh:47`](../package.sh#L47)：`PACKAGE_INCLUDE_SECRETS=1` 时
`.env` 进包。`.env` 里有 `INTERNAL_LLM_API_KEY`、`PUBLIC_LLM_API_KEY`、
`STATE_SIGNING_SECRET`、以及**内网网关地址**。

package.sh 自己的注释写着「这个包只能留在这台机器上部署——绝不能上传到任何
非本机的地方」。但**方式 B 的部署路径恰恰就是「上传 ZIP 到平台」**，
而且平台明确会把包分发到服务器并联合安全部门扫描。

三条同时被踩：

- 作品规范：「不得上传敏感凭证、密钥或未授权材料」
- 打包规范自检第 7 条：「检查 ZIP 中不包含密钥、密码、个人令牌」
- 仓库自己 8-21 那次 `chore: 清掉全仓公司标识与内网信息` 的意图

**这一条是本次审计里唯一一条可能带来仓库之外后果的问题。**
正解已经在 [`start.sh:57-72`](../start.sh#L57) 写好了：密钥走
`${RUNTIME_DIR}/env`，运维放一次，跨 release 稳定。

#### P0-3 `/readyz` 不探连通性，而嘉定独立网段大概率打不通内网网关

[`app/main.py:544`](../app/main.py#L544)：

```python
ready = settings.offline_demo or settings.llm.configured
```

`configured` 只看**变量填没填**，不看**打不打得通**。而官方文档 Q2 说得很清楚：
大赛服务器在嘉定独立网段，**与周浦、浦江、嘉定 T/P 网络隔离**——内网模型网关
在哪一侧没人在这个仓库里确认过，但「隔离」这个词已经足够让人担心。

如果真打不通，会发生的事是：`/healthz` 一路 ok、`/readyz` 一路 ready、
`start.sh` 一声不吭返回 0、平台判定部署成功，**而玩家看到的每一句都是兜底台词**。
这正是 [`start.sh:131`](../start.sh#L131) 注释里记着的 8-24 那次事故的同一种结局，
只是根因换了一个。

而 ADR-0007 的自动切换**接不住这一种**：它的判据是
`该令牌状态不可用` 这句原文（[`app/llm.py`](../app/llm.py) `quota_exhausted`），
网络不可达连不上那个分支。

好消息是探测能力已经有了——[`app/main.py:504`](../app/main.py#L504)
的 `/healthz?probe=1`，只是 `start.sh` 从来没调用过它。

#### P1-1 前端有一个 300×150 的空 canvas 常驻在页面上

实测 `document.querySelectorAll('canvas')` 返回两个，第二个是 300×150
（HTML canvas 的默认尺寸，说明它从没被 `fitCanvas` 初始化过）且
`offsetParent` 非空。不报错，但它是一块没人负责的可见元素。

#### P1-2 `.thread` 的 `scroll-behavior: smooth` 与逐句渲染打架

[`static/style.css:1684`](../static/style.css#L1684) 给 `.thread` 设了
`scroll-behavior: smooth`，而 [`static/chat.js:13`](../static/chat.js#L13)
的 `toBottom()` 用的是 `thread.scrollTop = thread.scrollHeight` 赋值。

赋值在 smooth 下变成一次**动画**，而 `paced()` 每 260–420ms 推一句、
每句都调一次 `toBottom()`——**每次都在打断上一次还没跑完的动画**。

实测：连打十一轮之后 `scrollTop` 停在 41 / 2663，屏幕上还停在开场白；
同一时刻 `scrollTo({behavior:'instant'})` 一步就到底。

> **诚实标注**：这一次是在脚本连续发言（间隔 2.5s）下复现的，
> 正常手速下单轮结束时能滚到底。所以定级 P1 不是 P0，
> 但机制是确定的，且修法零风险（改成 `behavior:'instant'`）。

### 视角 2 · 大赛评委

#### P0-4 全作品唯一的差异化判据，对打得差的人**整块不显示**

[`static/review.js:177`](../static/review.js#L177) 的
`<div class="group" id="contrastWrap" hidden>`，只有
[`review.js:773`](../static/review.js#L773) 那一行才会取消 hidden。
而 `paintContrast()` 有两条提前 return：

- 一把钥匙都没命中 → 整块不出现
- 「最佳档位效力 − 实际效力」≤ 0.15 → 整块不出现

代码自己的注释写着：

> **这是全作品唯一一条竞品没有的判据第一次被摆到玩家眼前。**
> …玩家自己打一局是看不见它的，**评审也一样**。

实测：一局十二轮、结局「转账」的对局里，这一块 `hidden === true`。
而 `balance_sim` 自己给的分布是**最低一档仍占 53.4%**，
novice 胜率 0.0%。也就是说——**最需要被解释「你差在时机」的那一半人，
恰好是这块解释不给他们看的那一半人。**

评委只玩一局，玩砸的概率过半。这一块不出现，作品的技术主张就只剩下文档在讲。

#### P1-3 「参赛宣言 50 字」这个必填字段仓库里不存在

CONTEST-POSITIONING §一 备了标题 / 团队名 / 思路概述三件套，
截图 3 的作品规范里还有一条「参赛宣言 50 字以内」，从来没人写过。
这是提交阶段会当场卡住的一格。

#### P1-4 没有 16:10 封面图，而封面图承担全部点击转化

规范建议 16:10、要「能代表产品核心场景」。当前唯一的图形产出是分享卡
（640×~700，≈1:1，[`history.js:166`](../static/history.js#L166)），
而且**「转账」结局的卡面写的是「守住的钱 ¥0 / 没有一句推动他」**——
这张图放在展示页第一位，转化必然很差。

#### P1-5 冷启动第一屏没有任何作品身份

实测：清空 storage 后打开根路径，第一屏是一个**没有标题、没有说明**的
转账确认页，一个大橙按钮写「确认转出」，唯一的说明是一行灰字
「模拟界面 · 不会产生任何真实交易」。

这个设计的意图很好（HANDOFF 8-25：「角色对调先做一遍，再解释」），
但它是为**已经知道自己在玩什么的人**设计的。评委从展示页点进来时不知道，
而一个反诈主题的比赛里，第一屏是个「向陌生账户转三十万」的按钮，
**误读成钓鱼页的成本比多写一行字高得多**。

### 视角 3 · 公司高管

#### P0-5 主张里最贵的那个数，赛期内一次都测不到

[POSITIONING.md](POSITIONING.md#L127) 把全部价值压在「24h 内转出取消率」上，
而 [AUDIT-RESPONSE-2026-08-23.md:36](AUDIT-RESPONSE-2026-08-23.md) 自己写着
这个数只能由交易系统回传、这个仓库里没有也不该有。

这不是新问题（8-24 的审计已经写过），但**换到高管视角它的性质变了**：
高管要的不是「你测过没有」，是「这东西归谁、下一步谁掏钱」。而
[POSITIONING.md](POSITIONING.md#L48) 断言归「用户风险与合规条线」的论据，
到今天仍然只有制度文本，**没有任何一位真实风控 / 合规从业者的确认**。

8-24 的审计给了成本最低的那一步（找 1-2 位同事看一眼、问三个问题），
**「面向公司全员报名」这个前提让这一步的成本进一步降到接近零**，但没人做过。

#### P1-6 法规锚点的条号自己都不敢写死

[CONTEST-POSITIONING §二.2](CONTEST-POSITIONING.md) 已经诚实地记着两条不确定：
前两条在不同信源里条号不一致；更要紧的是**第一义务人写的是「银行业金融机构、
非银行支付机构」，证券公司是否直接适用没有把握**。

高管席上这是最容易被一句话问停的地方，而它至今是「下一步」里的一条，
不是已完成项。

#### P1-7 品牌资产用法有一处对内不一致

`app/scenario.py:661` 与 `static/index.html:39` 把诈骗收款方命名为
**「银联资金核查专户」**。这是现实里最常见的诈骗话术之一，写实没错——
但仓库自己在 8-21 的
`chore: 清掉全仓公司标识与内网信息` 里已经做过一次决定：
**「剧本里的真实银行名换成虚构行」**。银联是真实机构，这一处漏在了外面。

在一场公司内部的金融科技比赛里，把一个真实金融基础设施品牌摆在
「诈骗收款方」这个位置上，风险不高但完全没必要。

### 视角 4 · 投票用户

#### P1-8 玩完一局最可能拿到的是「¥0 / 没有一句推动他」，然后被要求去分享

实测走完十二轮的复盘首屏：`他还是转走了` / `¥0` / `最终信任 42` /
`使用轮次 12`，往下是分享卡按钮。

`最终信任 42` 这个数**没有量纲、没有参照**——42 是好是坏、满分多少、
劝住线在哪，屏幕上一个字都没说。
这与 [POSITIONING.md](POSITIONING.md#L152)「对用户：一次犹豫，不是一份成绩」
是矛盾的：既然不给成绩，就不该摆一个看不懂的裸数字；既然摆了，就得给刻度。

#### P1-9 分享卡上没有任何一条回到作品的路

[`static/history.js:210-307`](../static/history.js#L210) 画的全部内容是：
标题「AI 反诈劝阻」、结局徽章、守住的钱、三栏统计、K 线、百分位。

**没有二维码、没有链接、没有作品名 / 团队名。** 在一场靠票数排名的比赛里，
一张传出去的图片如果不能把人带回投票页，它就只是一张图片。

（这一条与 8-24 审计的 P0-1 不同：那一条讲的是卡上**多印了**参赛编号，
已经删掉了；这一条讲的是卡上**什么都没印**。）

#### P1-10 离线演示模式下老陈会复读，而离线模式正是路演推荐用的那个

实测一局里出现三对连续重复：

- 「你到底想说什么，能不能说重点。」× 2 连
- 「别念了，我又不是三岁小孩。」× 2 连
- 「这些道理我都懂，不用你教我。」× 2 连

[TECH-DESIGN.md:360](TECH-DESIGN.md#L360) 自己写着：
「两个同事互相截图时看到同一句话，这个卖点当场破产」。
而 HANDOFF 写着「路演用它（离线模式），别用它量任何数字」——
**路演正是同事互相看屏幕的场合。**

#### P1-11 离线模式的合规红线会把「引用骗子的话」判成自己违规

实测输入：

> 您刚才说他**保本**又说不承诺收益，这两句能同时成立吗？

界面当场弹出红色「合规红线 · 承诺收益 · 真实展业中这句要留痕」。

根因在 [`app/offline.py:75`](../app/offline.py#L75)：

```python
("guaranteed_return", re.compile(r"(保证|包管|一定).{0,6}(赚|不亏|收益|回本)|(稳赚|保本)")),
```

`保本` 裸匹配，不看是谁说的。而**「拆矛盾」这把钥匙的标准打法就是复述对方
那句「保本」**——等于产品在惩罚它自己教的最佳动作。

offline.py 顶部诚实地写了「这张表粗得毫不掩饰」，但**粗的代价落在了
最容易被路演打出来的一句话上**，而且落在「合规红线」这个作品自称最硬的
功能上。评委看到这一幕，会认为判分是错的。

#### P2-1 桌面端 70% 的屏幕是空白

1280×720 下，`#transfer` 实测 390×676，居中，其余全是米色背景。
展示页 iframe 大概率是宽屏，第一眼的观感是「一个没做适配的手机页」。

（这不是要推翻「界面照搬微信」那条根——手机版式是对的。
问题只在**手机版式外面那一圈空白没有被利用**。）

#### P2-2 首轮发言后轮次计数器不动

[`static/chat.js:213`](../static/chat.js#L213) 把 `turnCurrent` 设为服务端
`meta.round`，而 [`app/engine.py:183`](../app/engine.py#L183) 的
`round_ = state.round + 1` 报的是**刚打完的那一轮**。
开局 [`opening.js:109`](../static/opening.js#L109) 又把它初始化成 `1`。

于是：开局显示「第 1 轮 / 12」（含义：即将打第 1 轮）→ 发第一句 →
仍然显示「第 1 轮 / 12」（含义：已打完第 1 轮）。**用户看到的是计数器卡住了。**
第二句之后才开始动。同一个标签前后两种语义。

#### P0-6 「不做传播」与「靠票数排名」是一个还没拍板的正面冲突
