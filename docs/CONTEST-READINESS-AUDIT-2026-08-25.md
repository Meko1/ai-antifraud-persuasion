| 团队成员 | 1–3 人（1 名队长 + 0~2 名队员） | ⚠️ 表单里当前只有一人，**要不要拉人是产品所有者的决定**，不是技术问题 |

### 1.2 提交阶段（截图 3/4 · 报名前请阅读）

**作品提交须知**

- 队伍 = 1 名队长 + 0~2 名队员，**以战队为单位**提交与展示
- 作品须原创、不侵犯第三方知识产权；**演示链接需可在浏览器正常访问**
- 前台默认展示**马甲昵称**与参赛信息，真实姓名可选；**部门信息固定展示**
- 提交后进入**初审**，留意个人中心作品状态与系统通知
- 赛程节点、通道截止以平台公告为准

**作品规范**

| 条目 | 约束 | 本项目现状 |
|---|---|---|
| 标题 / 宣言 / 思路 | 20 / **50** / 200 字 | ❌ **「参赛宣言 50 字」这个字段本仓库从来没写过**，CONTEST-POSITIONING §一 只备了三件套 |
| 在线链接 + 图片 | 必须有可访问链接，**至少 1 张图**；视频可选 | ⚠️ 图一张都没准备 |
| 封面图 | **建议 16:10**，清晰、能代表核心场景 | ❌ 没有 16:10 素材。分享卡是 640×~700（≈1:1，[`static/history.js:166`](../static/history.js#L166)），**不能直接当封面** |
| 桌面端作品 | 需提供**可嵌入网页**的 Web 展示方案 | ❌ **见下面 P0-1，当前的响应头明确禁止被嵌入** |
| 内部数据 | 须脱敏，**不得上传敏感凭证、密钥** | ❌ **见下面 P0-2，`PACKAGE_INCLUDE_SECRETS=1` 正好在干这件事** |

**作品提交细则**

- 参赛组别按作品类型选：金融财经 / 开发辅助 / 其他创新方向
- 所需资源（虚拟机 / 测试环境 / 接口）如实填写
- **禁止刷票、恶意拉票**；平台记录投票与互动行为，异常数据复核
- 审核驳回后可修改重新提交

### 1.3 展示与评选（截图 2 · 作品样例页）

这一屏是**投票用户真正会看到的界面**，本仓库此前所有文档都没有描述过它：

- 左上：作品标题 + 标签组 + 团队名 + 成员名 + 职能标签 + 一句参赛宣言
- 中部：**三个页签 —— 图集 / 演示视频 / 作品展示**
- 中部覆盖层：**弹幕**（评论以弹幕形式飘过截图之上）
- 右侧：**当前票数 + 「为作品投票」按钮**
- 右下：**评论区（最新 / 最热），带「精选评论」与楼中楼回复**

**这一屏对产品的三条硬含义：**

1. 「作品展示」页签几乎一定是把在线链接**嵌进 iframe**——这与
   「桌面端作品需提供可嵌入网页的 Web 展示方案」是同一句话的两种说法。
2. 用户是**先看图集、再决定要不要点进去玩**。第一张图承担全部转化。
3. **票数是这场比赛的可见计分板**，而
   [POSITIONING.md](POSITIONING.md#L159) 明确把「分享率」判成作废指标。
   这个冲突不是文档问题，是真实取舍，见 §二·视角 6。

## 二、六个视角的问题清单

编号规则：`P0` = 可能让作品直接不成立；`P1` = 明显掉分；`P2` = 打磨。
每条都带仓库内证据，没有证据的写成「待确认」而不是断言。

### 视角 1 · 资深专家（架构 / 工程 / 安全）

#### P0-1 响应头明确禁止被嵌入，而大赛展示页大概率就是 iframe ✅ 2026-08-25 已修（`9253667`）

[`app/main.py:104`](../app/main.py#L104) 与 [`app/main.py:110`](../app/main.py#L110)：

```
Content-Security-Policy: ... frame-ancestors 'none'
X-Frame-Options: DENY
```

实测（`curl -D-`）两条头都在生效。含义是：**任何页面都无法把这个作品嵌进
iframe**。而作品规范白纸黑字要「可嵌入网页的 Web 展示方案」，样例页上又确实
有一个「作品展示」页签。

一旦平台用 iframe 呈现，投票用户在展示页上看到的是一块空白或
「拒绝连接」——**而作者自己点在线链接是好的，很可能到最后都不知道**。

修法很便宜且不降安全等级：加一个环境变量，把允许的父页面来源做成白名单，
**默认仍然是 `'none'`**，只在部署到大赛平台时显式填一个域名。

#### P0-2 打包开关会把真实密钥打进要上传的 ZIP ✅ 2026-08-25 已挡（`9253667`）

[`package.sh:47`](../package.sh#L47)：`PACKAGE_INCLUDE_SECRETS=1` 时
`.env` 进包。`.env` 里有 `INTERNAL_LLM_API_KEY`、`PUBLIC_LLM_API_KEY`、
`STATE_SIGNING_SECRET`、以及**内网网关地址**。

package.sh 自己的注释写着「这个包只能留在这台机器上部署——绝不能上传到任何
非本机的地方」。但**方式 B 的部署路径恰恰就是「上传 ZIP 到平台」**，
而且平台明确会把包分发到服务器并联合安全部门扫描。

三条同时被踩：

- 作品规范：「不得上传敏感凭证、密钥或未授权材料」
- 打包规范自检第 7 条：「检查 ZIP 中不包含密钥、密码、个人令牌」
- 仓库自己 8-21 那次 `chore: 清掉全仓公司标识与内网信息` 的意图

**这一条是本次审计里唯一一条可能带来仓库之外后果的问题。**
正解已经在 [`start.sh:57-72`](../start.sh#L57) 写好了：密钥走
`${RUNTIME_DIR}/env`，运维放一次，跨 release 稳定。

#### P0-3 `/readyz` 不探连通性，而嘉定独立网段大概率打不通内网网关 ✅ 2026-08-25 已修（`9253667`）

[`app/main.py:544`](../app/main.py#L544)：

```python
ready = settings.offline_demo or settings.llm.configured
```

`configured` 只看**变量填没填**，不看**打不打得通**。而官方文档 Q2 说得很清楚：
大赛服务器在嘉定独立网段，**与周浦、浦江、嘉定 T/P 网络隔离**——内网模型网关
在哪一侧没人在这个仓库里确认过，但「隔离」这个词已经足够让人担心。

如果真打不通，会发生的事是：`/healthz` 一路 ok、`/readyz` 一路 ready、
`start.sh` 一声不吭返回 0、平台判定部署成功，**而玩家看到的每一句都是兜底台词**。
这正是 [`start.sh:131`](../start.sh#L131) 注释里记着的 8-24 那次事故的同一种结局，
只是根因换了一个。

而 ADR-0007 的自动切换**接不住这一种**：它的判据是
`该令牌状态不可用` 这句原文（[`app/llm.py`](../app/llm.py) `quota_exhausted`），
网络不可达连不上那个分支。

好消息是探测能力已经有了——[`app/main.py:504`](../app/main.py#L504)
的 `/healthz?probe=1`，只是 `start.sh` 从来没调用过它。

#### P1-1 前端有一个 300×150 的空 canvas 常驻在页面上

实测 `document.querySelectorAll('canvas')` 返回两个，第二个是 300×150
（HTML canvas 的默认尺寸，说明它从没被 `fitCanvas` 初始化过）且
`offsetParent` 非空。不报错，但它是一块没人负责的可见元素。

#### P1-2 `.thread` 的 `scroll-behavior: smooth` 与逐句渲染打架

[`static/style.css:1684`](../static/style.css#L1684) 给 `.thread` 设了
`scroll-behavior: smooth`，而 [`static/chat.js:13`](../static/chat.js#L13)
的 `toBottom()` 用的是 `thread.scrollTop = thread.scrollHeight` 赋值。

赋值在 smooth 下变成一次**动画**，而 `paced()` 每 260–420ms 推一句、
每句都调一次 `toBottom()`——**每次都在打断上一次还没跑完的动画**。

实测：连打十一轮之后 `scrollTop` 停在 41 / 2663，屏幕上还停在开场白；
同一时刻 `scrollTo({behavior:'instant'})` 一步就到底。

> **诚实标注**：这一次是在脚本连续发言（间隔 2.5s）下复现的，
> 正常手速下单轮结束时能滚到底。所以定级 P1 不是 P0，
> 但机制是确定的，且修法零风险（改成 `behavior:'instant'`）。

### 视角 2 · 大赛评委

#### P0-4 全作品唯一的差异化判据，对打得差的人**整块不显示** ✅ 2026-08-25 已修（`9253667`）

[`static/review.js:177`](../static/review.js#L177) 的
`<div class="group" id="contrastWrap" hidden>`，只有
[`review.js:773`](../static/review.js#L773) 那一行才会取消 hidden。
而 `paintContrast()` 有两条提前 return：

- 一把钥匙都没命中 → 整块不出现
- 「最佳档位效力 − 实际效力」≤ 0.15 → 整块不出现

代码自己的注释写着：

> **这是全作品唯一一条竞品没有的判据第一次被摆到玩家眼前。**
> …玩家自己打一局是看不见它的，**评审也一样**。

实测：一局十二轮、结局「转账」的对局里，这一块 `hidden === true`。
而 `balance_sim` 自己给的分布是**最低一档仍占 53.4%**，
novice 胜率 0.0%。也就是说——**最需要被解释「你差在时机」的那一半人，
恰好是这块解释不给他们看的那一半人。**

评委只玩一局，玩砸的概率过半。这一块不出现，作品的技术主张就只剩下文档在讲。

#### P1-3 「参赛宣言 50 字」这个必填字段仓库里不存在 ✅ 2026-08-29 已补（CONTEST-POSITIONING §一）

CONTEST-POSITIONING §一 备了标题 / 团队名 / 思路概述三件套，
截图 3 的作品规范里还有一条「参赛宣言 50 字以内」，从来没人写过。
这是提交阶段会当场卡住的一格。

#### P1-4 没有 16:10 封面图，而封面图承担全部点击转化

规范建议 16:10、要「能代表产品核心场景」。当前唯一的图形产出是分享卡
（640×~700，≈1:1，[`history.js:166`](../static/history.js#L166)），
而且**「转账」结局的卡面写的是「守住的钱 ¥0 / 没有一句推动他」**——
这张图放在展示页第一位，转化必然很差。

#### P1-5 冷启动第一屏没有任何作品身份 ✅ 2026-08-29 已修（见 §四）

实测：清空 storage 后打开根路径，第一屏是一个**没有标题、没有说明**的
转账确认页，一个大橙按钮写「确认转出」，唯一的说明是一行灰字
「模拟界面 · 不会产生任何真实交易」。

这个设计的意图很好（HANDOFF 8-25：「角色对调先做一遍，再解释」），
但它是为**已经知道自己在玩什么的人**设计的。评委从展示页点进来时不知道，
而一个反诈主题的比赛里，第一屏是个「向陌生账户转三十万」的按钮，
**误读成钓鱼页的成本比多写一行字高得多**。

### 视角 3 · 公司高管

#### P0-5 主张里最贵的那个数，赛期内一次都测不到

[POSITIONING.md](POSITIONING.md#L127) 把全部价值压在「24h 内转出取消率」上，
而 [AUDIT-RESPONSE-2026-08-23.md:36](AUDIT-RESPONSE-2026-08-23.md) 自己写着
这个数只能由交易系统回传、这个仓库里没有也不该有。

这不是新问题（8-24 的审计已经写过），但**换到高管视角它的性质变了**：
高管要的不是「你测过没有」，是「这东西归谁、下一步谁掏钱」。而
[POSITIONING.md](POSITIONING.md#L48) 断言归「用户风险与合规条线」的论据，
到今天仍然只有制度文本，**没有任何一位真实风控 / 合规从业者的确认**。

8-24 的审计给了成本最低的那一步（找 1-2 位同事看一眼、问三个问题），
**「面向公司全员报名」这个前提让这一步的成本进一步降到接近零**，但没人做过。

#### P1-6 法规锚点的条号自己都不敢写死

[CONTEST-POSITIONING §二.2](CONTEST-POSITIONING.md) 已经诚实地记着两条不确定：
前两条在不同信源里条号不一致；更要紧的是**第一义务人写的是「银行业金融机构、
非银行支付机构」，证券公司是否直接适用没有把握**。

高管席上这是最容易被一句话问停的地方，而它至今是「下一步」里的一条，
不是已完成项。

#### P1-7 品牌资产用法有一处对内不一致 ✅ 2026-08-29 已修（见 §四）

`app/scenario.py:661` 与 `static/index.html:39` 把诈骗收款方命名为
**「银联资金核查专户」**。这是现实里最常见的诈骗话术之一，写实没错——
但仓库自己在 8-21 的
`chore: 清掉全仓公司标识与内网信息` 里已经做过一次决定：
**「剧本里的真实银行名换成虚构行」**。银联是真实机构，这一处漏在了外面。

在一场公司内部的金融科技比赛里，把一个真实金融基础设施品牌摆在
「诈骗收款方」这个位置上，风险不高但完全没必要。

### 视角 4 · 投票用户

#### P1-8 玩完一局最可能拿到的是「¥0 / 没有一句推动他」，然后被要求去分享

实测走完十二轮的复盘首屏：`他还是转走了` / `¥0` / `最终信任 42` /
`使用轮次 12`，往下是分享卡按钮。

`最终信任 42` 这个数**没有量纲、没有参照**——42 是好是坏、满分多少、
劝住线在哪，屏幕上一个字都没说。
这与 [POSITIONING.md](POSITIONING.md#L152)「对用户：一次犹豫，不是一份成绩」
是矛盾的：既然不给成绩，就不该摆一个看不懂的裸数字；既然摆了，就得给刻度。

#### P1-9 分享卡上没有任何一条回到作品的路 ✅ 2026-08-29 已修（见 §四）

[`static/history.js:210-307`](../static/history.js#L210) 画的全部内容是：
标题「AI 反诈劝阻」、结局徽章、守住的钱、三栏统计、K 线、百分位。

**没有二维码、没有链接、没有作品名 / 团队名。** 在一场靠票数排名的比赛里，
一张传出去的图片如果不能把人带回投票页，它就只是一张图片。

（这一条与 8-24 审计的 P0-1 不同：那一条讲的是卡上**多印了**参赛编号，
已经删掉了；这一条讲的是卡上**什么都没印**。）

#### P1-10 离线演示模式下老陈会复读，而离线模式正是路演推荐用的那个

实测一局里出现三对连续重复：

- 「你到底想说什么，能不能说重点。」× 2 连
- 「别念了，我又不是三岁小孩。」× 2 连
- 「这些道理我都懂，不用你教我。」× 2 连

[TECH-DESIGN.md:360](TECH-DESIGN.md#L360) 自己写着：
「两个同事互相截图时看到同一句话，这个卖点当场破产」。
而 HANDOFF 写着「路演用它（离线模式），别用它量任何数字」——
**路演正是同事互相看屏幕的场合。**

### 2026-08-29 · 顺着上一条往下查，五个场景的档案里又找出六处

> （[`history.js`](../static/history.js) 卡头那行小灰字）。
> 真正缺的是**路**——码和链接。

卡尾新增一块：一句「扫码，换你去劝一次」+ 作品名 + 二维码 + 给人读的地址。

**这一块为什么允许做，写清楚免得下次被自己的规矩挡回去**：
[POSITIONING「不做什么」](POSITIONING.md)那条线是 P0-6 建议的拍法——
**允许为「让人看懂」做设计，不允许为「让人多打几局」做设计**。
二维码属于前者（它只帮人找回来，不改变对局），连胜奖励属于后者。

**二维码指向哪里**：默认就是当前访问地址（`location.origin`），
本地、内网、目标服务器都不用配。只有作品被别人的页面代理或嵌套、
浏览器看到的地址不等于该扫到的地址时，才去改 `index.html` 里那行
`<meta name="af-share-url">`——**静态文件实时读盘，改完刷新就生效，不用重启**。

**编码器是自己写的**（[`static/qr.js`](../static/qr.js)，字节模式、版本 1–10、
纠错 M/L）。理由是这个仓库的两条硬约束：零 npm 依赖、零构建；
而 CDN 更不行——大赛服务器在独立网段，一个连不上的 CDN 会让分享卡当场少一块。

自己写这种算法的风险很实在：**画出来像模像样，但扫不出来**，肉眼复核完全无效。
所以验证分两层：

- [`tests/frontend/qr.test.mjs`](../tests/frontend/qr.test.mjs) 把掩码钉死，
  拿 Python `qrcode` 库的矩阵**逐格比对** 32 组（v1/v2/v3/v5/v6/L10，含中文与长链接）。
  钉死掩码是因为选哪个掩码是各家自己的启发式——实测 segno、Python qrcode、
  本实现在同一条文本上选出三个不同的掩码，而八种掩码都是合法、扫得动的码。
- **真解码**：拿 OpenCV 的 `QRCodeDetector` 对自动选码的输出逐条解，八条全部解回原文；
  最后又对**实际生成出来的那张分享卡 PNG** 解了一次，拿回 `http://127.0.0.1:61614/`
  （E2E 那次的临时端口），路是通的。opencv 只是一次性取信手段，不进 requirements。

> 顺带记一条实测发现：**segno 1.6.6 在字节模式下会多补一个 `0x00` 填充字节**
> （`write_padding_bits` 里 `8 - length % 8` 在已经对齐时返回 8 而不是 0）。
> 它编出来的码照样能扫，但不是规范的最小编码，所以参考样本没用它。
> 第一版样本正是栽在这儿，记下来免得下一个人再查一遍。

### 2026-08-29 · 内网 token 用尽那天，接不接得住要能提前知道

起因是所有者确认了两件事：**嘉定那台机器能访问内网网关**（P0-3 担心的
网络隔离没有发生），**但默认模型的 token 可能用尽**。

后一件本仓库撞过三次（2026-08-15 / 08-22 / 08-23，每次持续 8 小时以上），
[ADR-0007](adr/0007-automatic-failover-to-a-named-public-model-on-quota-exhaustion.md)
的自动切换**早就实现好了**，这次不需要新写。缺的是另一样：

**这条降级链路在用上它之前，没有任何办法被验证。**
`/healthz` 的 `llm_failover` 只报"切没切过"，答不了运维在部署当天真正要问的
那个问题——*token 明天用尽的话，这台机器接得住吗*。接不住有两种，两种都是
安静的（`/healthz` 一路 ok，只是每一句台词都变成兜底台词）：

| 接不住的样子 | 原先能不能提前发现 |
|---|---|
| 压根没配 `PUBLIC_LLM_*`，没有退路 | ❌ 要等到用尽那天 |
| 配了，但地址/密钥/模型名写错或账号欠费 | ❌ 切换会"成功"然后立刻再失败，最后落回兜底台词，**比没配还难查** |

三处补上：

- `llm_failover` 多一栏 **`fallback`**（退路是谁：provider / model / protocol），
  **没有退路时是 `null`**——这一位是"这个进程没有退路"唯一的对外说法。
- `/healthz?probe=1` 多探一次退路，结果落在 **`llm_probe_fallback`**。
  探退路要趁还没用上它的时候。
- `start.sh` 把这两种情况各印一段醒目警告，带下一步该改哪个变量。
  与既有的网关探测一样**不影响退出码**——退路没配不等于部署失败。

**验证**：`tests/test_llm_failover.py` 新增 4 条（退路是谁、没有退路时为 null、
`probe_fallback` 探的是退路那一个而不是当前生效那一个、没有退路时返回 None）；
`tests/test_api_contract.py` 那条 `/healthz` 字段契约跟着从四栏改成五栏。

### 2026-08-30 · 拦截屏那句落点：重音从职称换回 Helper

所有者问「"你是他的投资顾问"需不需要改」。**角色不改，那一句改。**

**角色为什么不能动**——它是三处的地基，不是戏服：

1. 合规红线两条（荐股／承诺收益）是**执业**禁区，没有这个身份，
   「你自己要出事」那一整块没有着力点；
2. 七把钥匙「没有一把是给建议」直接来自「只能问，不能荐」（核心矛盾一）；
3. **剧本本身写着它**：`app/scenario.py` 里老陈的人设是「你的证券账户是李经理
   给你开的，他是你的投资顾问，**你们一年也说不上几句话**」——那句"说不上
   几句话"正是劝阻难度的来源之一。拆掉身份要重写五个场景的人设提示词。

[README §五](../README.md) 的辩护成立。

**那一句为什么该改**——两条，第二条是硬的：

- **它和上一句在同一屏上互相削弱。** 上一句刚说「拦下他们的那句话，往往就差
  **一个人肯说**」（任何人都可以是那个人），下一句立刻收窄成
  「而**你是他的投资顾问**」（你得是个专业人士）。而 `style.css` 自己写着
  这一句"是整个作品的那一句话"——**整个作品的重音落在了一个职称上。**
- **外部实证支持的恰恰不是那一半。** [EVIDENCE §五](EVIDENCE.md) 的 ROLESafe
  （CHI 2026，n=144）里得分最高的一组叫 **Helper——"去劝一个受害者"**，
  F1 0.85，三种角色第一。**它测的是"你去劝人"，不是"你是专业人士"。**

改法：重音换回 Helper，身份降成下一行的**约束集**。

> 有人正要做同样的事，而这一次，肯开口的是你。
> 你是他的投资顾问：看得见他的账户，看不见他的生活。你可以问，
> 但不能替他做决定，也不能向他推荐任何产品——那是执业红线。

**顺手补掉一个老问题**：合规红线此前是**中途惊喜**——玩家从没被告知不能荐，
直到第 N 轮突然弹出一条红色「合规红线 · 荐股」。规则该在开局讲，
讲的时候顺手把核心矛盾一与三都交代了。

**验证**：`tests/frontend` 138、`tests/e2e` 14 全绿（Python 未涉及）；
新增三条断言钉住"落点不许是职称""身份不许被删""合规红线必须开局讲"。

> **顺带修了素材脚本一个时序 bug**：它在「坐到对面」还被锁着的 450ms 内
> （`HANDOFF_ARM_MS`，防连击）就去点，点在禁用态上什么都不发生，
> 然后卡在下一个 waitFor 上超时——**症状看着像页面坏了，其实是脚本手快**。
> 已改成先等解锁。

### 2026-08-31 · 演示视频：也写成脚本，顺手抓出素材里一处换人

清单挂了两天的「演示视频还没做」清掉了：`tools/capture_video.mjs`，
一条命令出一支 51 秒的 1920×1080 MP4。

**为什么不用录屏软件**：和截图那套同一个理由，而且更重——改一句文案就得
重录重剪，而这个仓库两周里改了七八次文案。**为什么不用 ffmpeg**：本机没有，
装它要动系统；而 **Chrome 自己就能编码**（`MediaRecorder` 支持
`video/mp4;codecs=avc1`，本机 151 实测支持），配 `canvas.captureStream()`
就是完整链路。于是这个脚本和仓库其余部分一样：**零 npm 依赖、零外部二进制**。

做法两步：CDP `Page.startScreencast` 收真实帧 → 另开一页把帧铺到
1920×1080 画布上（手机屏在左，字幕在右）录成 MP4。**画面上没有一帧是排出来的。**

真打一局三分钟，视频要压进一分钟，所以每一章写明占几秒，编码时线性映射。
脚本跑完会打印**实录/成片的比值**：静止的屏幕拉长看不出来，
**只有对话那一章不行**（有 SSE 逐句到的动效，拉慢一眼看得出），
比值离 1 太远会自己报警。

#### 路上踩的四个坑，都留在注释里

| | 症状 | 因 |
|---|---|---|
| 1 | 片子里**换了个人**：前 12 秒拦截屏印「你是**她**的投资顾问」，第 20 秒起坐着老陈 | 钉客户只能在工作台做，而转账屏与拦截屏在它之前 |
| 2 | 第 9 秒本该是拦截屏，实际是第 1 轮对话 | `Page.reload` 发出去就返回，后面的 waitFor 全命中**旧页面**；且首屏那次 `loadGame()` 已 `saveGame()`，重载直接续局 |
| 3 | 最后六秒字幕写「同一句话，换个时候说」，画面上是另一块 | 第 6 轮主动结束 → 没走到结局 → `contrastFacts()` 返回 null → 整块不画。**现在打满十二轮，并且滚不到那一块就直接报错** |
| 4 | 画面整体落后字幕将近八秒 | 帧时间戳用了"Node 收到的时刻"。ack 是异步的，帧在 WebSocket 里排队，而 Node 正 await 着一串 evaluate。**改用 Chrome 给的 `metadata.timestamp`** |

另外两处写在代码里：`captureStream(0) + requestFrame()` 在这个负载下**大量丢帧**
（同样 1275 次调用，成片只剩 35 秒 / 200 KB），换回 `captureStream(fps)`；
编码整段占着页面主线程，**边编边轮询会把 `Runtime.evaluate` 饿死**
（实测直接拖到超时），改成先按成片时长睡过去再问。

`phone-01` / `phone-02` 一直是随机某位客户，`phone-03` 起才是老陈——
而图集里这两张是相邻的。两个脚本现在都在**首屏之前**钉住老陈，
用的是界面自己那把钥匙（`aap.pick.sid`，「换一位客户」写的那个键），
**没有为出素材改任何产品行为**。

成片在浏览器里逐点抽帧复核（3/9/15/20/27/34/38/42/49 秒），
每一章的画面与字幕都对得上；`phone-05` 跟着屏上那句改名「七把钥匙」。
