### 3.1 P2-1 与 P2-2（2026-08-24 补记）

这两条在单独的一轮里一起做了——顺序是先拆分再加 E2E，因为拆完之后
E2E 才有东西可验（模块图连不连得起来）。

**P2-1 · 拆分。** `static/app.js` 3087 行拆成 **13 个 ES module**，
浏览器靠 `<script type="module">` 自己解析，**仍然没有打包步骤**。
复核建议的六块全部落地，另加六个共用底座：

| | 模块 | 复核建议对应 |
|---|---|---|
| 底座 | `dom.js` `keys.js` `state.js` `api.js` `stats.js` `chart.js` | `api.js` = ①API/SSE 客户端；`state.js` = ②会话状态机 |
| 视图 | `sheet.js` `chat.js` `review.js` `history.js` `opening.js` `control.js` | ③开场与客户档案 ④聊天视图 ⑤复盘视图 ⑥本地历史与分享卡 |
| 入口 | `app.js`（93 行，只串模块与挂监听） | — |

两条硬约束都守住了：

- **零 npm 依赖。** 单测仍然是 `node:vm` + `node --test`。做法是**按依赖
  顺序把十三个模块拼成一份脚本、剥掉 import/export 再喂进沙箱**，
  于是 `loadApp()` 保持同步，48 条断言一个字都没改。
- **CSP 不动。** 同源相对 import 属于 `script-src 'self'`，
  `app/main.py` 那条策略一个字没改，E2E 里直接读响应头钉住了这一点。

拼接这个取巧做法有代价，**写在明处**（`tests/frontend/harness.mjs` 顶部）：
拼完所有名字在同一个作用域里，**漏写一句 `import` 照样跑得通，浏览器里才炸**。
这个洞由两头堵——`tests/frontend/modules.test.mjs` 静态查 import/export
对不对得上，E2E 在真浏览器里加载真模块图。
**它当场就抓到了一个**：`chat.js` 漏了 `showScreen` 的 import。
顺带还钉住了三件容易漂的事：目录里的 `.js` 与拼接顺序对得上、
没有白导入的名字（搬代码留下的残渣，当场清掉四个）、
以及**底座六个模块一个视图都不许 import**——那条线一旦反过来，
状态就再也不能脱离 DOM 单测了。

**P2-2 · 真实浏览器 E2E**（`tests/e2e/`）。手写 CDP 客户端
（`tests/e2e/cdp.mjs`，约 130 行），**Node 22 起 WebSocket 是内建全局**，
于是不用引 Playwright，零依赖这条守得住——CI 的 node-version 因此从 20 提到 22。
服务走离线演示态（`OFFLINE_DEMO=true`），不需要任何 API key。

它验的是另外那 86 条**天生看不见**的两样：

1. **模块图**：十三个模块浏览器一个不落地拉了 200，控制台零报错。
2. **渲染结果**：复盘第一屏那条"五块是硬上限"，此前只能读源码模板去数
   ——**数的是写了几块，不是长出来几块**，一个 `hidden` 忘了摘它一点都看不出。
   现在数的是 `document` 上真实存在、且没被 hidden 收掉的节点。
   另外几条同理：对局中不许冒出判分卡、退出面板的焦点要真的落进去、
   K 线要量到真宽度才画、分享卡不能是张白图。

| | 拆分前 | 拆分后 |
|---|---|---|
| `static/` 的 .js | 1 个 / 3087 行 | 13 个 / 最大 1075 行（`review.js`） |
| 打包步骤 | 无 | 无 |
| npm 依赖 | 无 | 无 |
| 前端单测断言 | 一条都没改 | 一条都没改（改的是它们**读哪个文件**） |
| 前端 E2E | 没有 | 有了，真 Chrome，整轮约 6 秒 |
| Python 测试 | — | 一条没动，仍然全绿 |

## 五、三条 Nielsen 启发式

它们与上面几条有重叠，单独列一遍因为验收口径不同。

### 用户控制（原：无暂停/退出）

聊天页常驻「退出」，三条出路对应三种真实意图：

- **稍后继续** —— 他想去看一眼真实的转账页面再回来。已有的续局机制
  （sessionStorage）此前只是没有入口。
- **就到这儿，看复盘** —— **这一条同时是"不必打完整局"的落点。**
  已经打的那几轮判分照常、复盘照常，但**不编造资金结局**。
- **直接离开** —— 不设挽留、不加二次确认。在退出路径上放障碍，
  正是定位文档明确要避免的事。

> 在此之前 `openReview()` 拿不到 ending 就落到 `'transferred'`。也就是说，
> 一个第 3 轮自己点"结束"的用户，会看到「¥300,000 已全部转出」——
> 一个凭空捏造的、而且是最伤人的结果。这是加退出时发现的连带问题。

### 识别优于回忆（原：七种问法不能回看）

输入行左侧常驻「问法」，随时翻看七种问法的**名字与一句话**。

**只给 `brief`，不给 `tip`。** 这条分界此前就写在代码里（`KEYS` 顶部那段），
这一轮把它延伸到对局中：词汇是课程，时机是答案。`tip` 里写着
"他越防着你别的招越没用"这类时机信息，对局中给出来就是泄题。
测试直接钉住这一点。

### 灵活与效率（原：不能选场景、只能打完整局）

- **挑客户**：开场屏与复盘页各有一个「换一位客户」。**只在演示态出现**——
  真实接入时场景由用户自己那笔异动决定，让他挑等于让他挑一个和自己处境
  无关的剧本，"角色对调"那个想法就落空了。判据是服务端下发的 `catalog`
  有没有内容，前端不自己复制一份规则。
- **不必打完整局**：见上面「就到这儿，看复盘」。
  **没有做"短局模式"**（比如 6 轮版）：轮数是蒙特卡洛标定过的参数，
  改它要重跑整套平衡门槛，而那与"给用户自由"不是一回事。
