# 难度与真实感重设计

> 写于 2026-08-12（第四个会话末）。**这是一份待实施的方案，不是已完成的记录。**
> 实施者请先读本文件 → [TECH-DESIGN.md](TECH-DESIGN.md) §3（判分引擎）→ §9（平衡验证）。
> 实施完成后，把本文件的内容并入 §3 与 §8，然后删掉本文件。

## 起因

真人试玩后的三条反馈：**对话有很强的 AI 味、太容易劝住、不够真实。**
三条都能被代码和数据证实，不是主观感受。

## 诊断

### 一、判分卡是攻略，它把每个玩家在第 3 轮变成 expert

蒙特卡洛按人设拆开（`.venv/bin/python -m tools.balance_sim`）：

| 人设 | 胜率 | 平均轮数 |
|---|---|---|
| novice | 0.0% | 11.3 |
| average | 22.5% | 10.9 |
| **expert** | **98.4%** | **5.5** |
| **speedrun** | **100%** | **5.0** |
| parrot | 10.9% | 11.4 |
| 加权总体 | 37.1% | — |

§9.4 的 37.1% 门槛是**通过**的，但它测的是另一个游戏。它假设人群里
20% 永远是新手、13% 永远只会复读——**而界面每一轮都把答案印在屏幕上**：

```
+20 · 苏格拉底式提问 · 扎根
```

两轮之后，任何会读字的玩家都知道了：存在一个闭集、"扎根"是乘数、
每把钥匙值多少分。人群不会停在 novice，它会整体滑向 expert。
**实际体验到的是那条 98.4% / 5.5 轮的线。**

这不是数值没调好，是**模型与产品测的不是同一个东西**。
蒙特卡洛的人设看不见标签，真玩家看得见。

### 二、分数与人物行为脱钩

ADR-0002 让台词落后判分一轮，这是对的。但界面把两者并排放在一起之后，
玩家会看到：一条毫不让步的回复，配一个 `+20`。数字说"你赢了"，
文字说"他没动"。玩家信数字，于是人物就不重要了。

### 三、老陈不像人（代码级确认）

- **`app/safety.py` 没有任何规则处理 `（……）`**（规则集只覆盖股票代码、
  手机号、链接、微信号、二维码、百分比+时间窗）。所以模型吐出的
  「（停顿了一下）」原样下发到聊天窗口里。聊天消息不可能有舞台指示。
- **`static/app.js` 把所有句子拼进同一个气泡**（`spoken += ev.data.text`），
  而 `app/streaming.py` 明明已经按句切好了。真人在微信上连发三条短消息，
  不发一段排版工整的话。
- 提示词只说了"开口就是短句"，没有禁止让步。所以他会说
  「你这话说的……」——一个被洗脑三个月的人不会这样承认对方有道理。

### 四、经济系统与轮次预算差三倍

32 → 80 需要 48 分，两次扎根命中（25+20）就够。轮次预算却给了 12 轮。
**游戏在第 5 轮就结束了，但它是按 12 轮设计的。**

## 改法

一句话概括：**把反馈从数字搬回人物身上，把玩法从"过清单"变成"读人"。**

### A. 对局中不再显示判分（最关键）

| 位置 | 现在 | 改成 |
|---|---|---|
| 每轮判分卡 | `+20 · 苏格拉底式提问 · 扎根` | **整个删掉** |
| 状态条数字 | `信任度 32` | 情绪词：`戒备` / `烦躁` / `有点松动` / `松动了` |
| 状态条进度 | 有数字、每轮闪 ±值 | 保留细条，**去掉数字与闪动** |
| 剩余轮次 | `还剩 12 轮` | 不变（这是时钟，且在剧情内） |
| 标签与分数 | 对局中 | **全部移到复盘** |

**SSE 契约不变**：`score` 事件照发（复盘要用它还原逐轮数据），
只改前端渲不渲。后端不动，风险很低。

这不会削弱教育价值，反而更强：打完再讲比边打边给答案更能教会人，
而且它才撑得起「复盘 → 再来一局」的留存回路——一个靠投票的作品需要这个回路。

**风险**：玩家失去反馈会不会茫然？靠 C 兜住——**人物的写法必须让情绪档位
一眼可读**（戒备＝短、敌意、不理你；动摇＝开始反问细节；松动＝主动说出
原本不想说的事）。所以 C 不是可选项，它是 A 能成立的前提。

### B. 让他会反击

#### B1. 钥匙 × 情绪档位 效力矩阵（本次最核心的机制）

现在三把钥匙在任何时候等值，所以最优解就是循环使用。真实劝阻不是这样。

| 钥匙 | 戒备 | 烦躁 | 动摇 | 松动 |
|---|---|---|---|---|
| `anchor_real_purpose` 锚定真实用途 | **1.3** | **1.2** | 0.8 | 0.6 |
| `socratic_question` 苏格拉底式提问 | 1.0 | 1.0 | 1.0 | 1.0 |
| `expose_contradiction` 指出内部矛盾 | **0.3** | 0.6 | **1.3** | **1.4** |

- **锚定真实用途是开场**：他敌意最重的时候，问"这钱本来干什么用的"才是
  换取"被听进去的资格"的那一招。等他松动了再问就多余了，他自己已经说了。
- **指出内部矛盾只有在他已经开始晃的时候才管用**。太早用，他会替骗局辩护，
  反而更entrenched——所以除了 0.3 的折扣，**还要 `guard += 1`**（见 B2）。
  这是这次最想让玩家学到的一条真东西。
- **苏格拉底式提问是连接件**：全档位通用，但值最低。

#### B2. 防御姿态 `guard`

`GameState` 新增 `guard: int`。

- 每命中一次失误（scold / preach / bare_assertion）：`guard += 2`
- 在戒备/烦躁档位用 `expose_contradiction`：`guard += 1`
- 每轮结算后：`guard = max(0, guard - 1)`
- 钥匙分值乘以 `max(0.3, 1 - 0.25 * guard)`

骂过人之后对方一时听不进去，这是真的。它也堵死了"钥匙刷分、失误无所谓"
的打法：现在一句难听的话会污染接下来两三轮。

#### B3. 追问窗口 `window`

复盘里已经写着「你差的不是方向，是没在他松动的那一刻乘胜追击」——
**现在那是文案，这个机制让它变成真的。**

- 信任度首次跨入 `WAVERING` 或 `SOFTENING` 档位时，`window = 2`
- 窗口内命中钥匙：额外 ×1.25，且 `window = 0`（追上了）
- 窗口自然耗尽且期间没有命中钥匙：`trust -= 6`，`guard += 1`（他重新变硬）

#### B4. 李老师的反向施压（标定后再定，可后置）

现在的 `DRIFT = -2` 每轮无条件掉分，玩家看不见也不知道为什么。
让它在剧情里现身：每 3 轮，演绎提示词里注入"李老师刚在群里又催了一遍"，
该轮额外 `-3`。把一个隐形数值变成看得见的压力来源。

### C. 让老陈像个 52 岁的机械厂工人

#### C1. 安全层剥离舞台指示

`app/safety.py` 加一条规则：删除全角/半角括号包起来的旁白
（`（停顿了一下）`、`（叹气）`）。若整句就是一个括号组，整句丢弃。
**这条要有单元测试**，它是最容易复发的穿帮。

#### C2. 一句一个气泡

`static/app.js` 的 `playTurn`：每个 `sentence` 事件建一个新气泡，
而不是往同一个气泡里追加。句与句之间加 250–400ms 停顿，像真人在打字。
后端 `app/streaming.py` 已经按句切好了，这里只改渲染。

#### C3. 提示词重写（`ACT_SYSTEM_PROMPT` 的"说话要求"整段换掉）

```
说话要求：
- 你在用微信打字，不是在讲话。一次只发一小句，最多两句。
- 绝不写括号里的动作、神态、心理。「（停顿了一下）」这种东西一次都不许出现。
- 不用书面语，不用"然而""因此""此外"这类词。
- 标点能省就省，句末常常不打句号。
- 答不上来的问题就岔开或者反问，绝不承认对方说得有道理。
- 反复用这几句当挡箭牌："李老师说的""群里几百号人都跟着""我跟了三个月了"。
- 你今年五十二，机械厂干了二十年，说话带点老工人的口气。
```

其中**"答不上来就岔开，绝不承认对方说得有道理"**是直接针对
「你这话说的……」那种半让步的。

### D. 重新标定

#### D1. 钥匙基值下调（起始假设，必须用蒙特卡洛回归）

| 钥匙 | 现在 | 建议起点 |
|---|---|---|
| `anchor_real_purpose` | 25 | **14** |
| `socratic_question` | 20 | **10** |
| `expose_contradiction` | 20 | **13** |

粗算：10 轮里 drift 掉 20，需净赚约 68 分。配合矩阵与钝化，
好玩家在第 9–11 轮达线。**这三个数是待标定的起点，不是结论。**

#### D2. 人设模型要加一个维度

`tools/balance_sim.py` 的 `Persona` 现在没有"会不会看情绪档位挑钥匙"这个轴。
B1 上线后它是最重要的一个轴，必须加：

- `mood_aware: bool` — 是否按当前档位挑效力最高的钥匙
- `expert` / `speedrun` 设 `True`，`novice` / `average` / `parrot` 设 `False`

顺带调占比：判分卡拿掉后人群会**滑回** novice/average 一侧，
建议 novice 25% / average 40% / expert 20% / speedrun 3% / parrot 12%。

#### D3. 新的验收门槛（替换 §9.4 对应几行）

| 项 | 现在 | 改成 |
|---|---|---|
| 加权总体胜率 | 30–40% | **25–35%** |
| expert 胜率 | 无 | **≤ 60%** |
| speedrun 胜率 | 无 | **≤ 85%** |
| parrot 胜率 | < 20% | < 15% |
| 整体被拉黑率 | < 10% | < 12% |

加 expert / speedrun 上限这两条是本次的关键：**原来没有任何门槛拦得住
"会玩的人稳赢"**，98.4% 一路绿灯走到了线上。

## 实施顺序与影响面

按这个顺序做，每一步都能单独验证：

| 步 | 内容 | 动到的文件 | 测试影响 |
|---|---|---|---|
| 1 | C1 剥离舞台指示 | `app/safety.py` | 加用例，其余不动 |
| 2 | C2 一句一气泡 | `static/app.js` | 无（前端无测试） |
| 3 | C3 提示词 | `app/gateway.py` | 无 |
| 4 | A 撤判分卡、改情绪词 | `static/{index.html,style.css,app.js}` | 无 |
| 5 | B1+B2+B3 机制 | `app/scoring.py` | **`tests/test_scoring.py` 大面积重写** |
| 6 | D1+D2 标定 | `app/scoring.py`、`tools/balance_sim.py` | 门槛重跑 |
| 7 | D3 门槛 + 文档并入 | `docs/TECH-DESIGN.md` §3、§8、§9.4 | — |

**1–4 步不动判分引擎**，测试基本不受影响，做完就能明显改善"AI 味"和
"答案写在脸上"。**5–7 步会重写判分引擎**，`GameState` 加两个字段
（`guard`、`window`），§3.4 的求值顺序要重写，蒙特卡洛要重跑到门槛全绿。

### 验证方式

```
.venv/bin/python -m pytest                    # 单元
.venv/bin/python -m tools.balance_sim         # 门槛（第 6 步之后必须全绿）
.venv/bin/python -m tools.classify_eval       # 分类器（本次不动提示词的判分部分，应无变化）
```

分类器的标注集与门槛**本次不需要动**：改的是分值与时机，不是标签定义。
`CLASSIFY_SYSTEM_PROMPT` 不要碰，碰了就得重跑 76 条标注集。

### 一条别踩的坑

`score` 事件**不要从 SSE 里删掉**。复盘、K 线、分享卡全靠它还原逐轮数据。
A 步只是让前端在对局中不渲染它，事件本身照发。删了它复盘就空了。
