## 为什么要转

这轮评审拿承办方的公司背景重新量了一遍定位，结论是一条**选题错配**：

**承办方是互联网券商，核心竞争力恰恰是不靠投顾人海。**
以营业部网点为主的传统券商有庞大的投顾队伍，一套投顾陪练在那里
有明确的业务 owner 和培训预算；互联网券商的组织结构里这个角色的规模和中心度都低得多。

后果不是"市场窄"，是**内部找不到人接**：没有业务线 owner、没有预算、
没有推广渠道，评委席上大概率没有一个人的 KPI 与"投顾话术水平"直接相关。
拿到奖也只能停在 demo。

**但同一套资产换个对象，匹配度从最低变成最高：**

| 产品里已有的 | 互联网券商真实拥有的 |
|---|---|
| 「资产异动预警：客户清仓 / 大额转出」 | 自营券商与基金代销平台**真实看得到这个信号**——产品里那条预警本来就是照它写的 |
| 老陈 / 周淑琴 / 老刘 / 月娥姐 / 顾之然 | 就是平台上的存量用户画像（含 29 岁的顾之然） |
| 荐股群、王老师、"内部消息" | 投资者社区是这类骗局在中文互联网的实际招募场之一 |
| 七把钥匙 + 闭集分类器 | 可**反向**用于识别诱导话术，不只用于训练 |

外加一条外部推力：《反电信网络诈骗法》给金融机构压了实打实的风险提示与
劝阻义务。**这不是"要不要做"，是"迟早要做"。**

> **判分引擎、五个场景、效力矩阵、482 个测试全部不动。**
> 这次要改写的是那一页定位，不是那一套代码。这一点必须先说清楚，
> 否则下一个人会以为要重做。
>
> **执行完之后回填一句**：这条守住了。测试从 482 涨到 529（另加 17 个前端），
> 涨出来的全是新模块自己的（脱敏、留存、离线模式），
> **判分那一批一个断言都没改，`balance_sim` 一次都没重跑过。**

## 一、把定位改成「C 端异动干预」，写一页说明

> **✅ 做完了。** 改的是 [POSITIONING.md](POSITIONING.md) 的「一句话」与
> 「成功标准」两节，其余各节一字未动，旧版本留在 git 历史里。
>
> 改的时候撞出一条本文没预料到的连带：**旧「成功标准」写着"复盘第一屏是
> 维度画像（`paintKeyBars`）"，而 §3.2 的保留清单里没有这一块。**
> 两页文档会当场打架。处理是把那一条随定位一起改掉并写明理由——
> 能力画像是给要反复练的人看的，C 端用户只打一局，画像因此收进折叠。
> **定位页与执行清单不一致的时候，改定位页，不是偷偷不执行。**

**产出**：一页文档（建议直接改写 [POSITIONING.md](POSITIONING.md) 的「一句话」
与「成功标准」两节，旧版本留在 git 历史里），必须回答三个问题。

### 1. 接哪个信号

用户在自营券商 / 基金代销平台触发下列任一动作时进入：

- 清仓（持仓一次性归零）
- 大额转出（占账户资产比例超阈值）
- 与历史行为显著背离的赎回（如"五年只做定投的账户今天全部赎回"）

**这三条产品里已经有了**——`Scenario.facts` 那几行 `warn=True` 就是照它们写的
（chen「今日转出 ¥100,000 / 占 78%」、hang「五年零主动交易，今天一次清仓」）。
现在它们是布景，转向之后它们是**触发条件**。

### 2. 归哪条线

用户风险与合规条线（不是培训条线）。这一条决定了：
- owner 是谁、预算从哪出
- 评委问「谁接」时有答案
- 合规义务是推力而不是阻力

### 3. 怎么衡量效果

**不再用"玩家打了几局"这类参与度指标**，改用干预效果：

| 指标 | 口径 |
|---|---|
| **24h 内转出取消率** | 干预组 vs 对照组，触发后 24 小时内主动撤销转账/赎回的比例 |
| **24h 内撤单率** | 同上，针对已提交未完成的指令 |
| 完成率 | 三分钟对话走完的比例（低了说明太长） |
| 二次触发率 | 30 天内再次触发异动的比例 |

**必须能和对照组比**——没有对照组的干预率是无法解释的数字。

### 4. 形态本身

用户按下转账/赎回确认之前，App 里弹一次三分钟对话：
**让他扮演劝阻者，去劝一个和他处境一模一样的人。**

它为什么比风险提示弹窗强：**用户劝不动"老陈"的那一刻，会自己想到自己。**
这不是培训，是干预；不需要说服任何人来"练习"。

**产品定位一句话**：
> 不是投顾训练器，是券商在用户按下转账前的最后一次干预。

### 不做什么（沿用 POSITIONING 的写法）

- 不做成"考试"或"必须通过才能转账"——那会变成阻挠交易，合规上站不住，
  产品上也会被用户当障碍绕过
- 不在干预里给任何投资建议（现有的两条合规红线继续管着）
- 不因为转向就动判分闭集（七把钥匙、效力矩阵、五个场景一行不改）

## 二、跑一次自研金融大模型的分类对照评测，报两栏表

> **⚠️ 只做成一半，右栏仍是空的。全过程见 [TECH-DESIGN §9.3.1](TECH-DESIGN.md)。**
>
> **网关不是拦路的那一个**：8-22 探针 `ok: True`（claude-opus-5 / Messages 协议），
> 令牌已经恢复。拦路的是**自研金融大模型根本不在这台网关上**——
> One API 用现有令牌列出 25 个模型，全是通用模型，没有自研金融大模型；
> 换根路径 `/v1/models` 是同一份清单。**它需要另一套地址与凭证，仓库里没有。**
>
> 做出来的三件事：
>
> 1. **`tools/classify_eval.py --model / --protocol / --base-url`**。
>    ADR-0001 说"换模型不影响任何一个分值"，此前那句话连证伪的入口都没有。
>    拿到自研金融大模型凭证之后，填右栏就是换两个参数、连跑两次。
> 2. **第三套协议没有写，而且不该写。** 内网网关是 One API、OpenAI 兼容，
>    `app/llm.py` 那条路直接能用。自研金融大模型若也走这条路，一行命令就够；
>    若不是，那时候再照 `anthropic_client.py` 加。
>    **在拿到真实接入方式之前先写一个猜出来的客户端，写的是一份会烂掉的代码。**
> 3. **拿网关上一个国产通用模型（<对照模型>）跑了对照**，两次连跑
>    86.4% / 82.4%——**一次过、一次不过**。差 4.0 个百分点远超那条 1.5 的线，
>    但第 2 次那 8 条解析失败全是网关错误而非模型没按格式输出；
>    剔掉之后是 87.8% / 85.9%。**这一栏不能当结论用，更不能冒充自研金融大模型。**
>
> 顺手修掉一个坑：ChatCompletions 那条路的 `base_url` 要自己带 `/v1`
> （Messages 那条由 SDK 补），少了它会打到网关前端页面上、拿回一整页 HTML
> 和一个 HTTP 200，然后以一条裸的 `JSONDecodeError` 冒出来。现在报的是人话。

**为什么这件事性价比最高**：内部赛上「为什么不用自研金融大模型」几乎是必问题，
而这个项目**恰恰是全场最适合换模型的那一个**，却没把这一点讲出来。

> ADR-0001 把判分交给纯函数规则表，模型只做两件事：演绎 + **闭集分类**。
> 分类是典型的垂直模型能干好的任务，而**判分正确性完全不受模型能力影响**。
> 换模型只影响演绎质感和分类准确率，不影响任何一个分值——
> 这是三个月前就买好的单，现在到了兑现的时候。

### 怎么做

1. 摸清自研金融大模型的接入方式（endpoint、模型 id、协议是 OpenAI 兼容还是别的）。
   现有的 `app/llm.py`（ChatCompletions）与 `app/anthropic_client.py`（Messages）
   已经是两套协议实现、同一个端口，**加第三套照着 `anthropic_client.py` 写**，
   网关与编排层不用改（§6.4 的分层就是为这个准备的）。

   （§6.4：没有 temperature 了，同一份标注集两次连跑固有差 0.6~1.3 个百分点，
   小于 1.5 个百分点的变化不能当信号读）。
3. 报表已经现成：`accuracy_by_sid` 会按五个场景拆开。

## 三、服务端落对局数据 + 复盘砍到 5 块以内

### 3.1 落数据

> **✅ 做完了。** [ADR-0006](adr/0006-transcript-retention-for-the-pivot.md)
> 写清了例外范围（ADR-0003 只被推翻了一半：对局**状态**照旧客户端持有），
> `app/transcripts.py` 落库、`app/redact.py` 脱敏。**默认关**，
> `TRANSCRIPT_RETENTION=true` 才开——留存不该由"忘了配环境变量"决定方向。
>
> 两条硬要求各自落成了测试：
> - 脱敏 `tests/test_redact.py`（19 条）。**两侧都钉**：该挖的挖掉，
>   **不该挖的不许动**——金额与剧本人名一个字不能动，
>   脱宽一点点这份语料就训不出分类器，而那是留存的全部理由
> - 告知 `tests/test_transcripts.py`（13 条）。那句话由服务端随
>   `/api/game/start` 下发，**判据是"到底存没存"而不是"开关拨到哪边"**：
>   开关开着但没配 Redis 时一条都存不下去，这时候还说"会留存 90 天"，
>   是在为一件没发生的事道歉
>
> 一处本文没写、但落地时必须补的：**范围清单里"不存什么"比"存什么"更长**。
> 转向之后这段对话由一条真实资产异动触发，把那条异动一起存下来是最自然
> 不过的下一步，ADR-0006 把它划在了范围外。

**现状**：服务端**一条对局记录都没有**。`app/stats.py` 只有 5 个计数器
（games / turns / endings / hits / trust 分桶）。跑一万局也攒不下一条数据。

**为什么现在必须改**：形态 A（C 端干预）与形态 B（投资者社区治理）都要求落数据，
而这个赛道唯一可能的护城河就是数据飞轮——真实对话 → 专家标注 →
更准的分类器 + 更真的效力矩阵。**竞品抄走七把钥匙只需要一周，
抄不走三年的标注语料。**

**它会撞上 ADR-0003**（客户端持有签名状态、服务端不存任何东西）。
那条决策在比赛期是**完全正确**的取舍（部署简单、无状态、重启不丢局），
转向之后不再成立。**要新写一条 ADR 说明例外范围，不要偷偷改**——
ADR 的价值就在于反转时留下理由。

**两条硬要求**：
- **脱敏**：用户发言可能带姓名、金额、账号。落库前过一遍脱敏，
  且脱敏规则要有测试（可复用 `app/safety.py` 的思路）
- **明确告知**：8-22 已经在聊天页加了一行
  「对方是虚构客户，机构与人物均为虚构。本练习不构成投资建议；
  你输入的内容会发送至大模型用于生成回复。」
  落库之后这句话要**补上留存与用途**，且必须在用户开口之前出现

分享卡 → 说明文

这违背了它自己引用的那条研究（PUBG 后置屏 N=12 用户研究：
**玩家不会为了看懂一个指标跑去别处找解释，看不懂就直接忽略**）。
8-22 还往里加了两块（对照块、处置清单），把问题加重了。

**C 端用户比投顾更没耐心**，转向之后这一条从"设计瑕疵"升级为"能不能用"。

建议保留的五块（可讨论，但总数是硬上限）：
1. 结算卡（他最后按没按下确认）
2. **同一句话，换个时候说**——全作品唯一竞品没有的判据，不能砍

4. 处置清单（现实里还差这几步）——C 端干预的落点
5. 分享卡

**砍掉的不是删除，是收进折叠或移到"详细复盘"**。逐轮三段账、七把钥匙条、
本机记录这些对认真的人仍然有价值，只是不该挡在第一屏。

### 第 1、2 条做了什么（8-22 第十一个会话）

**第 1 条 · 前端测试**（`tests/frontend/`，`node --test tests/frontend/*.test.mjs`，已进 CI）

**零 npm 依赖是硬约束**：这个仓库没有 node_modules，打包规范里也不该多出一个。
所以没有 jsdom、没有 jest，只用 Node 自带的 `node:vm` 与 `node --test`——
把 `static/app.js` 整个装进沙箱里跑，`app.js` 本身一个字都没改
（顶层的 `const` 不会挂到 context 上，靠加载时拼一段访问器交出来）。

**它测得了什么、测不了什么，写在 `harness.mjs` 顶部**：测得了不碰 DOM 的判断
（`scoredTurns` / `breachTurns` / `reviewRows` / `resultAmount`），
测不了渲染结果——DOM 在沙箱里是个"问什么都答应"的替身。
复盘那条五块上限因此走另一条路：直接读源码里的模板。
**这一点必须写在明处，免得后来的人以为这套测试盖住了渲染。**

第一组测的就是 `degraded`：网关抖一下，那一轮不许进任何一个分母。

**第 2 条 · 离线演示模式**（`OFFLINE_DEMO=true`，`app/offline.py`）

打开之后**一个网络请求都不发**：台词取预置台词库，分类走关键词规则。
而**判分一格都不打折**——七把钥匙、效力矩阵、蓄势池、结局阶梯本来就是
纯函数（ADR-0001）。实测连打三轮：+8 / +4 / +14，档位从烦躁走到动摇。

**它演的不是"假装模型还活着"，演的恰恰是这个作品的技术主张**：
网关整个挂掉，这一局照样打得完、复盘照样算得出来。

三条边界：
- **与 ADR-0005 不冲突**。那条否掉的是运行期悄悄换供应商；这是启动期的
  显式开关，运行期照旧不自动切换任何东西
- **藏不住**：`/healthz` 报 `offline_demo: true`，聊天页第一行写着。
  一个看不出来是演示的演示，不是演示，是一场骗局
- **"数据去向"那句告知是替换不是追加**。第一版拼接，页面上先说
  "你输入的内容会发送至大模型"、再说"不调用大模型"——两句话打架的时候，
  用户只会记住错的那一句

**第二供应商仍然没做，而且这次是刻意的。** 它要的不是一个开关，是第二套
提示词标定：门槛（85% / 80% / 93%）是在现役模型上量出来的，换一家就得
重跑标注集、重调消歧规则（§9.3 里 8-15 换模型那一次就是这么栽的）。
离线模式买到的是"演示不会开天窗"，那是路演真正需要的东西；
"生产随时可切第二家"是另一件事，别用前者冒充后者。
